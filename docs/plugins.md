# 开发独立预览插件

## 包结构

```text
plugin.json
bin/your-plugin.exe
bin/your-importer.dll     可选
ui/index.html
ui/view.js
ui/style.css
ui/sdk.js                 可选，复制 sdk/web/index.js
ui/engine.wasm            可选
```

```json
{
  "api": 1,
  "id": "example.model",
  "name": "模型预览",
  "version": "1.0.0",
  "extensions": ["fbx"],
  "icon": "file-type",
  "executable": "bin/your-plugin.exe",
  "entry": "ui/index.html",
  "capabilities": ["view", "controls"],
  "provides": "example.model/1",
  "permissions": ["readFile"],
  "settings": [
    {
      "key": "defaultZoom",
      "type": "number",
      "label": "默认缩放比例",
      "help": "打开模型时的初始缩放。",
      "default": 1,
      "min": 0.1,
      "max": 8,
      "step": 0.1
    }
  ]
}
```

`api:1` 是本次重写的协议，没有旧版兼容入口。`revision` 由安装器生成，市场构建额外生成 `buildId` 内容指纹。同一格式匹配所有已启用插件；`capabilities` 决定视口、浮层和功能气泡，其中 `view` 与 `overlay` 可以同时声明 —— 那是同一个 `entry` 挂载两次，用 `role` 区分。具体契约与槽位规则见 [能力协议](specs/plugin-capabilities.md)。旧的 `view` 字段不再接受，入口统一为 `entry`。

## 插件图标

`icon` 可选，填写宿主图标集里的名字（小写 kebab-case）。插件不打包图标资源：宿主自己提供图形，插件只声明用哪个。这样避免了路径校验、格式白名单、体积上限和内容哈希这一整套问题，也防止包把自己伪装成另一个。

可用名称：

```text
archive  binary  braces  code  file-code  file-json  file-pen
file-text  file-type  film  image  info  music  presentation  table
```

不填，或填宿主不认识的名字，都会退回通用图标 —— **不会导致加载失败**。因此宿主后续扩充图标集时，已发布的插件不会被作废。名字格式（小写）、长度上限 40 则会在加载时校验。

侧栏的“插件设置”入口、插件管理卡片和市场卡片共用同一个图标。

## 插件设置

`settings` 是可选数组。**宿主读取声明后自己画出设置界面**，每个插件在设置侧栏有独立入口，点进去就是该插件的设置页；插件不需要提供任何表单标记，用户改的值由宿主校验、持久化并下发。

```json
{
  "key": "wrap",
  "type": "bool",
  "label": "自动换行",
  "help": "关闭后长行横向滚动。",
  "default": true
}
```

公共字段：`key`（必填，`[A-Za-z0-9._-]`，≤64，插件内唯一）、`type`（必填）、`label`（必填，≤80）、`help`（可选说明）、`default`（可选，缺省按下表推导）。每个插件最多 32 项。

| `type` | 界面控件 | 专属字段 | 缺省 `default` |
|---|---|---|---|
| `bool` | 开关 | — | `false` |
| `number` | 数字输入 | `min` `max` `step` | `0` |
| `select` | 下拉选择 | `options: [{value,label}]`（必填，≤64 项） | 第一个选项 |
| `text` | 单行文本 | — | `""` |

校验发生在两处，都失败得明确而不是静默降级：

- **清单加载时**：`default` 必须满足自己的 schema；`select` 必须有 `options`；`options` 的 `value` 不能重复；**未知 `type` 会让整个插件加载失败并出现在设置页的警告里**。这样新插件在旧宿主上会显式报错，而不是被渲染成错误的控件。
- **写入时**：`number` 会被夹到 `[min,max]` 并对齐 `step`；`select` 只接受已声明的选项；未声明的 `key` 直接拒绝。

宿主只持久化**与默认值不同**的项。把某项改回默认值即删除该覆盖，因此插件后续调整默认值会自动生效，不需要迁移。清单里已删除的设置项，存储中的残留值会被忽略。

插件有两个面，都能拿到设置：

**原生进程**收到 `params.settings`，是按声明补全默认值后的完整对象。开启文件时随 `open` 下发：

```json
{"id":1,"method":"open","params":{"session":"s1","path":"C:\\a.png","settings":{"defaultZoom":1.5}}}
```

自定义方法同样携带 `settings`；`release` 仅包含会话 ID。用户改动时宿主会主动发 `settings` 通知，插件应回一个 result 表示接受；返回 error 会在宿主侧记录，但**已存储的值不会被回滚**，插件下次 `open` 仍会看到它。

```json
{"id":9,"method":"settings","params":{"session":"s1","settings":{"defaultZoom":2}}}
```

Rust 插件可用 `ember_plugin_sdk::{settings, setting, settings_applied}` 免去手工解析。`settings`、`open`、`release` 是生命周期方法，由插件实现响应，网页不得作为自定义 RPC 调用。

**插件网页**在 `ready` 的载荷里拿到 `settings`，也可以用 `configuration()` 随时读取、用 `onSettings(fn)` 响应变化：

```js
import { ready, configuration, onSettings } from './sdk.js';
const { data, settings } = await ready;   // settings 与 data 同时到达
const zoom = Number(configuration().defaultZoom);
onSettings(next => { /* 应用新值 */ });
```

设置变化只会送到**当前已存在的会话**。宿主不会因为设置改变而自动重开已经打开的文件，因此插件应当自行决定哪些项对当前会话立即生效（例如文本插件的换行和行号），哪些只影响后续打开的文件。图片插件用“用户是否已手动操作”来区分：未手动缩放或平移的会话会立即应用“默认适应窗口”，操作过的会话保持当前视图。

## 原生进程协议

宿主使用包目录作为工作目录，隐藏控制台，连接 stdin/stdout。每行一个 UTF-8 JSON 对象。stdout 只能用于协议，不能写调试日志。插件可以使用 Rust、C++、.NET 或其他能生成独立程序的语言；运行依赖必须包含在包内或由安装环境提供。

请求：

```json
{"id":1,"method":"open","params":{"session":"s1","path":"C:\\Models\\chair.fbx"}}
```

成功响应：

```json
{"id":1,"result":{"yourPluginData":"any JSON shape"}}
```

错误响应：

```json
{"id":1,"error":"模型解析失败"}
```

`result` 的结构完全由插件定义。原生进程可以保留会话自己的索引、网格或分页缓存；视图通过后续自定义方法按需取数据。

```json
{"id":2,"method":"mesh-chunk","params":{"session":"s1","path":"C:\\Models\\chair.fbx","value":{"mesh":4}}}
```

会话回收时，如果进程还有其他会话，宿主发 `release` 和会话 ID。没有任何会话时直接终止进程。需要保留原生状态的插件应实现 `release` 清理；示例 SDK 对无状态插件默认返回 null。请求可以并发，响应必须回显正确 ID，禁止依赖响应顺序。

进程崩溃会令未完成请求失败，后续请求可启动新进程，但宿主不会猜测并恢复插件内部缓存。使用原生会话状态的插件，应能够根据请求中的 `session` 和 `path` 重建所需状态，或返回明确错误要求重新打开文件。

## 插件网页

```js
import {
  ready, controls, call, read, status, presented, onVisibility,
  setSetting, panel, postTo, onMessage,
} from './sdk.js';
const {data, file, role} = await ready;   // role 是 'view' 或 'panel'

// 同时声明 view + overlay 时，同一个 entry 会被挂载两次，用 role 决定这次画什么：
// 主视口画正文，浮层画功能操作区。
if (role === 'panel') renderPanel(data); else renderView(data);

// 在这里创建自己的渲染器，例如 Three.js、PDF.js、Canvas 或普通 DOM。
// data 是原生 open 的 result，file 只有 name 和 size。
controls([
  {id:'orbit',kind:'button',label:'环绕模型',icon:'fit',run() { /* 插件处理 */ }},
  {id:'grid',kind:'toggle',label:'显示网格',icon:'actual',active:true,run() { /* 插件处理 */ }},
  {id:'find',kind:'button',label:'搜索图层',icon:'search',
   run() { /* 打开自己的浮层 */ panel(true); }},
]);

// 两个挂载是两个文档，彼此看不见，所以插件内部通信走宿主这根不透明管道：
// 宿主只转发，不解析。谁拥有状态由插件自己决定。
if (role === 'panel')
  onMessage(payload => { if (payload.kind === 'status') showCount(payload.count); });
else
  postTo('panel', {kind: 'status', count: 17});   // 浮层没开时返回 false，不报错

const mesh = await call('mesh-chunk', {mesh:4});
const firstBytes = await read(0, 65536);
status('模型已加载');
await presented(); // 首次解析、解码与视图初始化真正完成后发送。
onVisibility(visible => { /* 暂停或恢复插件渲染循环 */ });
```

### 控件

| `kind` | 宿主行为 | 专属字段 |
|---|---|---|
| `button` | 点击时回调插件 | — |
| `toggle` | 画成可点亮的按钮，并反映状态 | `active: true` 表示点亮 |

控件对宿主是不透明的：它只负责聚焦插件、把控件 id 转发回去。插件想用这个按钮打开自己的浮层、切换模式还是弹别的东西，都由插件决定。

图标可用 `search/copy/plus/minus/fit/actual/up/down/text-wrap/save/rotate-ccw/hash/code`，未知名称显示通用功能图标。控件最多 16 个。

`active` 只有显式 `true` 才算点亮，其他值一律视为关闭——这样写错的声明不会让控件被误点亮。

### 搜索这类功能由插件自己做

宿主不认识"搜索"：没有搜索框组件，也没有 `kind: 'search'` 控件。要做搜索的插件按自己的需要组合三样东西：

1. 一个 `button` 控件，点击时用 `panel(true)` 打开自己的浮层；**打开浮层的控件应该声明成 `kind: 'toggle'` 并让 `active` 跟随浮层开关状态**，宿主会把打开中的按钮点亮，和「自动换行」是同一套状态语言；用普通 `button` 就丢掉了这个状态。浮层自己关闭时（✕、Esc）要用内部消息告诉视口，否则按钮会和实际显示不一致；
2. 浮层里调用 `mountSearchBar()`（来自随包分发的 `sdk-search.js`）：输入框、上一个/下一个、`n/m` 计数、Enter/Shift+Enter、Esc 关闭都由它提供，外观与宿主控件一致；
3. 匹配算法在插件里，`findOccurrences(text, query)` 给出全部 `[start, end)` 位置，高亮画在自己的视口上。

**同一个功能不要写第二遍。** 共享组件是插件侧代码：`npm run build` 会把它和 `sdk.js` 一起复制进包，并参与 `buildId` 计算，所以改共享组件会重新发布用到它的插件。**只有真正引用它的插件才会带上它**，没有浮层的插件包里不会多出这两个文件。文本编辑插件用的就是这个搜索条。

浮层和主视口是两个文档，插件内部要传状态就用 `postTo(role, payload)` / `onMessage(fn)`，宿主只转发不解析，`postTo` 返回对端是否挂载（浮层没开时是 `false`，不是错误）。通常由主视口持有匹配集，浮层只显示结果。

导航不经过插件的原生进程，因此不占用 `plugin_call` 的并发额度。

两个已经踩过的坑，做高亮前先看一眼：

- **在视口里画高亮**（换行与窗口化渲染都适用）：命中要对**字符**着色，把行按命中位置切成若干段、只把命中的子串包进 `<mark>`；整行点亮说明不了命中在行内哪个位置，也不好判断相邻命中。跳转分两种模式：换行模式没有固定行高网格，用 `scrollIntoView`；非换行模式是先改 `scrollTop` 再按窗口渲染，所以必须先滚动后渲染，顺序反了目标行还没生成。
- **在 textarea 里画高亮**（文本编辑插件的做法）：`textarea` 只在**获得焦点**时绘制选区，而焦点必须留给浮层里的输入框（否则用户打第二个字就断了）。所以命中由一层透明的镜像文本画在 textarea 上方，字体、内边距、`white-space` 必须逐项对齐，滚动事件里同步 `scrollTop`/`scrollLeft`。超大文本可以不画镜像，计数和跳转仍然有效。

### 写设置

`setSetting(key, value)` 让视图代用户改一个已声明的设置项（例如工具栏上的「自动换行」开关）。宿主按清单校验并持久化，随后照常通过 `onSettings` 回报结果——所以工具栏开关和设置页永远一致。

宿主会把当前主题写成 CSS 变量注入插件文档，**完整清单就是这些，没有别的**：

```text
颜色  --bg --canvas --panel --card --raised --hover
      --border --text --muted --faint --accent --accent-bg
形状  --radius-control --radius-pill --radius-card
      --control-h --control-h-sm --space-1..4 --field-label-w
字体  --font-ui --font-mono --mono-size --mono-leading
```

浅色与深色下同一组变量取不同值，随主题切换实时更新。加上这些形状与字体变量之后，**换肤不再只是换配色**：圆角、控件高度、间距、字体全部跟着走，凡是用了共享组件的插件都不用改代码。

**给 `var()` 写兜底值时要注意**：它会长期生效，所以颜色兜底必须是中性或透明的，不要写死某一种主题的颜色 —— 否则浅色窗口里会出现深色块。`--hover`（控件悬停底色）和 `--raised`（浮起的表面）最容易漏。

网页里还要 `<link rel="stylesheet" href="./sdk-ui.css">`：它既是共享组件库的样式，也提供与宿主一致的滚动条外观。插件网页是独立文档，**不链这份样式表就会露出平台默认滚动条**（浅色、带箭头、不随主题变化），在深色浮层里非常突兀。

### 共享组件库

`sdk-ui.css` 里现成的东西（都是宿主 token 驱动的）：

| 组件 | 用法 |
|---|---|
| `.ui-button` / `.ui-button.primary` / `.ui-button.on` | 普通、主操作、点亮态（`on` 与宿主工具栏同一个词） |
| `.ui-icon-button` / `.ui-icon-button.on` | 纯图标按钮 |
| `.ui-input` | 单行输入框，含焦点描边 |
| `.ui-fields` | 标签/取值列表（`dl > dt + dd`），文件信息面板就是它 |
| `.search-bar` + `mountSearchBar()`（`sdk-search.js`） | 搜索条：输入框、上一个/下一个、`n/m`、Enter/Shift+Enter、Esc |
| 滚动条 | 全局，链上样式表就有 |

**规则：优先用库里的组件。** 库里没有的，就用同一套 token 自己写，不要另造数值 —— 这样换肤时它照样跟着走。库里已有的组件不要复制一份改（文本预览与文本编辑曾经各写一份滚动条，结果文件信息那份漏了，深色浮层里露出白色默认滚动条；同一份实现只能有一个）。

### 文本类插件的留白标准

正文类视口（文本预览、文本编辑，以及以后任何显示文档正文的插件）统一按这一套留白，折行与不折行都一样。差别只应该来自内容和功能，不应该来自留白。

```css
:root {
  --text-pad-inline: 16px;   /* 正文左右的最小留白 */
  --text-scroll-lane: 8px;   /* 滚动条自己要占的道，与 kit 里 ::-webkit-scrollbar 的宽度一致 */
}
.text-column {
  /* 右边是"文字留白 + 滚动条道"：不折行时文字会一直排到内容框右缘，只留 16px 的话
     长行会顶着甚至钻到滚动条下面，折行时看着有留白、一开不折行就没了。 */
  padding: 0 calc(var(--text-pad-inline) + var(--text-scroll-lane)) 0 var(--text-pad-inline);
}
```

三条约束：

1. **内边距加在文字那一层，不要加在滚动容器的外层。** 滚动条永远贴着自己所属盒子的边缘，外层加内边距会把滚动条一起推进来 —— 那时滚动条就不在视口边缘了。
2. **滚动容器要铺到视口边缘**（`position: fixed; inset: 0` 或等价的满高满宽），这样滚动条才贴着视口。
3. **上下留白使用宿主安全距离**：宿主通过主题通道下发 `--safe-top` 和 `--safe-bottom`。将其加在正文滚动内容的首尾，不缩小滚动容器。沉浸模式包含浮动栏高度，非沉浸模式仅保留 12px 渐变及 6px 缓冲；切勿再次加上标题栏或功能栏高度。

第二条的具体含义：滚动条道不占 `clientWidth`，所以"文字列右端"由 `clientWidth - padding-right` 决定，而滚动条画在 `clientWidth..offsetWidth`。要留出可见的缝，`padding-right` 就必须大于滚动条宽度，多出来的那部分才是缝。

另外，镜像层（例如给搜索命中上色的那层）必须逐项复制正文的留白与字体度量，差 1px 就会让所有命中整体错位。

`ready` 表示与宿主建立连接并收到原生数据；`presented()` 表示插件自己的视图已经可用。初始化期间切换到其他类型不会回收这个会话。初始化失败调用 `presented(errorMessage)`；未完成视图在 120 秒后明确报错，避免损坏的插件永久占用缓存。

### 主视口同一时刻只有一个网页

主视口像显示器的输入源：只有当前视口插件的网页是挂载着的，切换到另一个插件就会把上一个卸载，它下一次被切回来时重新初始化。所以**视口网页不要依赖自己一直活着**：滚动位置、缩放这类只存在于网页里的状态，切走再回来会丢；插件网页运行在不透明源里（`sandbox="allow-scripts"`，没有 localStorage），也没法自己存。需要跨切换保留的状态请交给宿主：声明成设置项，或让原生进程持有。

唯一的例外是持有未保存草稿的会话：它的网页必须留着，因为草稿只存在于那个网页里，卸载就等于丢数据。草稿一解除（保存或撤销），它就和普通视口一样可以被卸载。

浮层与主视口互不影响：浮层只在自己打开时挂载。

页面脚本必须作为包内 JS 文件引用；模块、CSS、WASM 等资源通过相对路径加载。单个静态资源最多 32 MiB。禁止内联 JS 与网络脚本，第三方渲染库应打包进插件。插件完全控制页面；不要引用宿主 `src` 或依赖宿主 React 组件。

通用 `read` 每次最多 1 MiB，仅能读取当前会话文件。`clipboard(text)` 请求宿主写剪贴板，仅当前显示视图可用。涉及原生解析结果的大数据应分页或分块，不要将大型模型塞进单个 JSON 响应。

## 安装与验收

在“插件管理 → 插件市场”中直接安装，或选择已构建的包目录安装。构建脚本扫描仓库 `plugins`，每个插件源码目录还需提供 `listing.json`，包含 `summary`、`publisher`，以及可选的 `recommended`（见下：首启引导页只列出标了它的插件）。生成的市场目录与 `.plugins` 安装目录相互独立。添加新条目不需要修改宿主支持列表。

`npm run dev` 包含市场首次构建、前端服务、Tauri 后端监视和插件监视。插件修改后市场版本更新，开发宿主同步已安装的市场插件；卸载的插件不会被监视器自动重新安装。

**更新替换已安装的那一份，磁盘只留两个修订。** 安装不做原地覆盖：Windows 上有进程在跑的目录改不了名也删不掉，而且复制到一半失败会留下一个坏掉的安装。所以新修订落在旧修订旁边，切换靠 `revision` 大小，宿主只认最新的那个。为了不让它随版本数一直堆下去，每次安装完都会保留**当前修订 + 被它取代的那一个**（供回滚），更旧的按卸载同一条回收路径退休——还在被预览使用的修订会等那次预览结束再删。卸载会一次性退休该插件的全部修订。下载缓存按同一规则裁剪：只保留磁盘上还能用到的 `buildId` 对应的包（当前与上一个），其余删除，因此缓存里也不会积压历史版本，卸载后对应缓存一并清掉。

新增格式验收应满足：空宿主打不开该格式；安装包后能打开；禁用后新的打开请求失败；慢加载期间切换到其他插件后能再切回来；闲置后进程退出；重新打开可以重建。FBX/PDF/PSD 需要在插件包内真正实现相应解析与渲染，本原型不伪造这些格式的支持。

## 激活与气泡交互

清单可声明 `"activation": { "mode": "auto", "priority": 100 }`。省略时为 auto、0；manual 表示点击气泡进入。清单优先级越大越靠前；用户通过左侧插件列表拖动排序（越靠上越优先），右侧使用“自动激活”开关，不显示数字优先级。没有自动进入的视口时回退到手动视口；激活规则不取消任何后台初始化。设置变化从下一次打开文件生效。

气泡名称就是视口入口，控件操作会先聚焦所属插件。**功能栏同一时刻只有当前插件的按钮是展开的**：其余气泡收成一条名称，切换视口时以宽度动效过渡。所以插件不需要考虑"我的按钮会不会挤到别人"，也不必自己创建宿主视口切换器。编辑类插件可在保存成功、解除 `pending` 后调用 `fileChanged({returnToSource:true})` 刷新并返回自动视口；普通 `fileChanged()` 保持当前插件。没有修改时使用 `returnView()`。这两个桥接口不替插件保存内容；失败必须保留草稿。只有一个视口时仍留在该视口。

文本编辑与文本预览均提供 `ember.text/1`，二者安装时只选择一个解析源；编辑器也可独立安装。两者复用插件侧 `crates/text-document` 库，宿主不依赖文本解析实现。`npm run dev` 同时监听该库、插件及 SDK 的变化。

## 宿主浮层容器

声明 `capabilities` 含 `overlay` 的插件必须同时声明 `overlay` 尺寸，例如 `"overlay": { "width": 290, "height": 176, "anchor": "bottomRight" }`。宽高单位为 CSS 像素，指插件内容区（不含宿主 12px 的拖动条）；宽度范围 120–1600，高度范围 24–1200。`anchor` 可选，取 `topRight`（默认）、`topLeft`、`bottomRight`、`bottomLeft`，只决定面板首次出现的位置，用户拖动过以后以记住的位置为准。非浮层插件不能声明 overlay 尺寸。

宿主只提供两件事：一块可拖动的浮动面板，以及位置的保存与恢复。**面板里放什么完全由插件决定** —— 标题、关闭按钮、搜索框、纯信息文本都由插件自己画在 entry 网页里。宿主不提供标题栏、展开/收起按钮，也不提供位置重置按钮；在拖动条上双击可恢复默认位置。

面板默认是关的，由插件用 `panel(true)` 打开；只有浮层的插件也可以直接用底部气泡开关。面板只在打开期间挂载，关闭即卸载，所以插件不要指望关掉以后还留着上次的状态。

同时声明 `view` 和 `overlay` 的插件是同一个 entry 挂载两次：主视口一次、浮层一次，`ready` 载荷里的 `role` 告诉网页自己是 `"view"` 还是 `"panel"`。

浮层这次挂载是**次要挂载**：它不能上报 `controls` 或 `status`，也不能发送 `presented`、`pending`、`fileChanged`、`returnView`、`mutate` —— 生命周期、变更声明和文档写入都属于视口。越权调用会被宿主明确拒绝，不会静默忽略。其余能力（`call`、`read`、`copy`、`setting`、`panel`、`peer`）两边都能用。文件信息插件仅负责内容排版，宿主没有针对它的尺寸分支。

## 主视口尺寸与沉浸模式

视口大小是**宿主的决定**，插件既拿不到也不需要开关：网页永远占满自己那个框，只有框在变。设置里的“沉浸模式”切换的就是这个框，与插件无关。

- **普通模式**：标题栏与功能栏是纵向布局里的两个 flex 项，各自占掉窗口的上下一条，插件视口正好是中间剩下的那一段 —— 两条栏在结构上不可能压住内容，宿主也不用猜它们有多高。这时视口有一条 1px 描边和 12px 圆角，四周露出窗口底色，读起来是一块独立内容区。
- **沉浸模式**：视口铺满整个窗口，两条栏改成贴在窗口上的浮层，平时隐藏，鼠标靠近窗口顶部或底部才出现。

沉浸模式下两条栏**不接管自己画到的像素**：栏本身 `pointer-events: none`，只有里面的气泡（品牌、窗口按钮、文件信息、插件气泡、宿主按钮）吃指针。所以

- 气泡与气泡之间、栏与栏之间的空隙，指针直接落到插件上；
- 顶部那条整行拖拽区在沉浸模式下让出指针（拖窗口用品牌气泡，它本身就是拖拽把手）；
- 底部只有窗口最下方 6px 的一条感应带负责让功能栏显形，插件的滚动条轨道、最后一行文字、拖选都不受影响。

这是刻意的取舍：**视口是插件唯一需要理解的矩形**。滚动条轨道、选区、视觉边缘都长在那个矩形上，沉浸模式只是把矩形变成整个窗口，插件不必为两种模式写任何分支。宿主自己的浮层也画在同一个矩形里，所以浮层同样不会被两条栏或视口边界裁掉 —— 位置仍然由宿主决定，插件决定浮层里画什么。

视口底部的**淡出由宿主统一提供**（普通模式下视口最后 44px，用 `--canvas` 渐隐到透明），画在插件网页之上、插件浮层之下。所以内容顶到底边是渐隐而不是被一条硬线切断，插件也不必自己写边缘渐变 —— 写了只会和宿主那层叠加。宿主浮层不会被这层淡出影响，它是功能区域，被渐隐会看起来像插件的 bug。深度写在宿主的布局变量里，插件不要为此另造数值；换肤下发的是颜色与形状 token，不含它（插件网页是独立文档，读不到宿主变量）。

## 文本组件与位置共享

文本预览、代码预览、Markdown 预览及文本编辑均使用插件侧共享文本组件。完整说明与手动验收见 [文本插件族](specs/text-plugins.md)。`fileNames` 补充无扩展名匹配；`viewState()` 提供按文件与契约隔离的不透明阅读状态，保存后重新创建会话也可恢复。

安全距离在功能栏显隐时保持稳定，只随模式、栏尺寸及窗口布局变化更新。`onTheme()` 可用于触发组件重新测量。渐变由宿主统一绘制且不接收指针事件。共享文本组件同时设置滚动定位的安全边界；Markdown 正文与大纲复用相同变量，图片适应窗口使用扣除安全距离后的区域。

## 市场来源与安装交互

分成三层，各自的职责不重叠：

| 层 | 是什么 | 对应的动作 |
|---|---|---|
| 宿主 | 只有外壳，没有任何预览实现，也不打包任何插件 | 解析插件源、校验、安装、运行 |
| 插件源 | 一份远程目录 `catalog.json`，列出有哪些插件、当前是哪个构建 | 插件信息获取 |
| 包链接 | 目录条目里的 artifact，指向源基地址下的一个 zip | 插件下载 |

所以一个刚装好的应用**预览不了任何东西**，直到用户从插件源装了插件。首次启动会打开一次引导页（见下），之后一切增删都在“插件管理 → 插件市场”里。

### 插件源

宿主从 `src-tauri/plugin-sources.json` 读取来源列表，发行版把它作为资源随应用提供：

```json
{
  "api": 1,
  "sources": [
    {
      "name": "官方源",
      "catalog": "https://github.com/Ruszero01/ember-peek/releases/latest/download/catalog.json",
      "base": "https://github.com/Ruszero01/ember-peek/releases/latest/download/"
    }
  ]
}
```

- `catalog` 读目录，`base` 用来拼 artifact 名。两者都必须是 http(s) 地址、`file://` 或绝对路径；**相对路径会被拒绝**，因为它只能相对于宿主进程的工作目录解析，那不是任何镜像能依赖的位置。
- 最多 8 个源。同一个插件出现在多个源里时，哈希相同就是同一个包的镜像，安装按顺序回退，先前失败的镜像不影响安装；哈希不同则视为冲突，保留第一个并在界面报告。
- 目录读取有 10 分钟缓存（界面轮询 `market_list`，不能每次请求都走网络），超时 8 秒。读取失败的源沿用上一次成功的结果，并在界面列出原因，而不是让市场静默地少掉插件。
- 改配置不需要改代码：`EMBER_MARKET_SOURCES` 指向另一个来源文件即可（开发时用来验证真实的远程源）。

### 首次启动引导页

应用是外壳，所以首次启动会打开一次引导页：列出插件源里标了 `recommended` 的插件（没标则取列表前几项），让用户勾选安装，而不是把整份目录铺开。勾中的**走与市场完全相同的公开安装流程**（`market_prepare` 下载校验 → `install_plugin` 复制），宿主不会因为“这是首次启动”而走任何特殊路径。也可以选择“稍后再说”。

已安装插件和已被用户卸载的插件不会出现在引导页的可选列表里。答案记录在 `host-state.json` 的 `onboarded` 字段中，因此引导页只出现一次；即使当时不装，之后也能在插件市场里装。

出现原因也如实显示：插件源读不到、条目不可用、平台不匹配，都会在引导页里列出来，而不是显示成一个空的列表。单个插件安装失败不会中断其余插件，失败项单独列出。

### 平台声明

`targets` 声明这个包的原生程序能跑在哪些 `系统-架构`（如 `windows-x86_64`，最多 8 项，小写）。省略表示不限制，因此 `targets` 出现之前构建的包照常加载。打包脚本会按当前构建主机自动写入这一项，并在 `buildId` 里覆盖它。

市场的处理是：条目声明的平台不含当前主机就不展示，并给出说明；`prepare` 会再拒绝一次；解包后还会用包内清单的 `targets` 复核一次。三层都用同一份声明，所以一个 Windows 包不会被误装到别的平台上，直到启动程序才失败。

### 发布：目录与包格式

`npm run plugins:dist` 产出可直接上传的发布物（`--dist` 隐含 release 构建，不会把 debug 可执行文件发出去）：

```text
.release/catalog.json                              供插件源读取的目录索引
.release/ember.text-0.1.0-<buildId24>.zip          每个插件一个包
```

把 `.release/` 整体上传到任意静态位置（例如 GitHub Release 的 assets，路径与 `plugin-sources.json` 里的 `base` 对上），插件源即可读取。包名按 `id-版本-buildId` 内容寻址，所以新构建不会覆盖旧包。每次发布只保留索引引用的那些包：`plugins:build` 与 `plugins:dist` 都会清掉目录里没有被当前索引引用的陈旧包。

包是 **zip**，`plugin.json` 位于压缩包根目录，其余条目是相对路径：

```text
plugin.json
bin/your-plugin.exe
ui/index.html
ui/sdk.js   ui/sdk-ui.css   ui/sdk-search.js
```

压缩包里的 `plugin.json` 把安装期才赋值的 `revision` 写成 `0`，因此同样的输入总是产生同样的字节，目录里的 `sha256` 才有意义（安装时由安装器自己分配 `revision`）。条目名必须是普通相对路径：反斜杠、盘符、绝对路径和 `..` 一律拒绝，符号链接在解包时同样拒绝；声明的解压总量与**实际写出**的字节数都会受上限约束。这些拒绝发生在写入任何文件之前。

目录的每个条目自带 `version`、`buildId`、`sha256`、`size` 和界面需要的展示字段，所以市场卡片不必先下载就能显示版本、图标与扩展名。

其中 `recommended` 表示“适合首次安装”：首启引导页只列出这些条目，其余留在插件市场里。它来自插件源码目录的 `listing.json`（和 `summary`、`publisher` 写在一起），所以宿主不硬编码任何插件 id——换插件源或换一批推荐项都不需要改代码。一个源什么都没标时，引导页取列表里的前几项，而不是把整份目录铺开。

### 校验边界

下载后校验两件事，各自回答不同的问题：

- `sha256` 对应**传输**：拿到的字节就是目录索引的那个文件。校验在解包前完成，因此被替换的包不会有机会落盘。
- `buildId` 对应**身份**：解包后的清单声明的构建与目录索引的是同一次构建。字节完整但装错了包（例如目录索引 A、镜像给了 B）会在这里被拒绝。

**`buildId` 不等于签名。** 它由打包脚本从内容算出，宿主只能核对"包内声明 == 目录声明"，无法重算它证明内容与指纹一致。目录本身若可被替换，这套校验就失去意义，所以：

- 签名接口已经预留：目录可以声明 `signature`。**当前版本没有实现校验，因此声明了签名的目录会被直接拒绝**，而不是被当作已校验。未签名的目录是当前信任模型的诚实表述，签名在发布签名工作落地时接管这里。
- 装进来的原生程序与用户同权限，没有 OS 级沙箱，所以第三方来源应视为与手动安装程序等价：市场会展示真实来源地址和大小，用户点击才算确认。

下载物按 `sha256` 缓存（开发 `.plugin-cache`，发行版在应用数据目录的 `plugin-cache`），重复安装不重复下载；缓存内容与目录记录不符时会被丢弃并重新下载。缓存只保留磁盘上仍能用到的那几个修订（见[安装与验收](#安装与验收)），卸载后对应条目也会清掉。

### 开发时的市场

开发环境不读发行版那份来源文件，而是把最近一次插件构建结果当作本地镜像（`.marketplace/`，`plugins:build` 与监视器持续重建它），因此插件源码一改，市场里就出现新构建，安装走的是与线上完全相同的 zip 下载与校验路径。开发环境**故意不读官方源**：本地构建比已发布的更新，优先用已发布的话开发循环会装到旧包。

需要验证真实远程源时，用 `EMBER_MARKET_SOURCES` 指向一个来源文件即可（它只在 debug 构建里生效）。

### 数值拖动工具栏控件

`controls()` 支持 `kind: "scrub"`：声明有限的 `value`、`min`、`max`（`0 < min < max`），可选 `suffix`。宿主默认显示数值，按住并上下拖动时显示虚拟刻度；向上增大、向下减小，松开/取消后恢复数字。`run(value)` 接收绝对数值；插件重新发布控件以同步滚轮等其他操作引起的变化。支持方向键、Home 和 End。图片插件以百分比声明缩放范围，保留适应窗口和原始尺寸按钮。
