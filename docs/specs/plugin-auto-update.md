# 插件自动更新

通用设置提供“自动更新插件”，默认关闭，开关存入宿主 `host-state.json`。旧状态文件缺少此字段时按关闭处理；设置窗口与预览窗口从原生快照读取同一个值，不依赖网页或窗口一直存在。

开启后，宿主启动时以及每小时检查一次配置的插件源；运行中开启通常在五秒内开始第一次检查。检查串行执行，失败不缩短周期，关闭后不发起下一批自动更新；已进入原子替换的更新允许完成。关闭期间下载完成的工件在替换前重新检查开关。

仅对仍已安装、具有已记录目录来源且该目录仍在配置中的插件应用更高 SemVer 版本。按插件原目录单独选择版本，不因另一个目录提供更高版本而换来源；本地导入／工坊插件没有市场目录时跳过。同版本 `buildId` 改变、降级、已卸载插件或未安装的推荐插件不会触发自动安装。禁用的已安装插件可更新，仍保持禁用状态。

下载、大小／SHA-256 校验、解包与工件声明校验沿用市场安装流程。替换在安装锁内重新确认开关、已安装状态、目录来源及版本，避免下载期间卸载或手动升级后被重新安装／覆盖。未保存内容沿用已有替换保护：该插件跳过，其他插件继续，下次周期重试。插件设置、启用状态与查看位置遵循原有替换行为，成功更新会恢复正在预览的文件。失败保留旧插件并记录诊断，不打开确认窗口。

开发环境已有的两秒本地构建同步独立于此开关，继续按 `buildId` 跟进源码重建。正式发布插件行为变化仍需要更高插件版本；尚未首次发布的 `0.1.0` 基线在实际发布时才升版。`defaultValue` 等可选控件字段兼容 `api:1`，不要求升级协议版本。

自动测试覆盖默认关闭与持久化、同版本重建不更新、正常升版、禁用状态保留、未保存内容保护、关闭／卸载后的替换复核，以及多源下只更新原目录。Windows 手动验收需启动新编译的宿主，验证通用开关、重启后值保留、窗口关闭后的后台运行，以及正在预览文件的恢复。
