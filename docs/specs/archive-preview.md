# 压缩包预览规范

状态：0.1.0 基线。插件 `ember.archive`，协议 `api:1`，包版本 0.1.0。宿主不为它新增任何字段、命令或界面分支。

压缩包预览把「里面有什么」和「其中一个文件长什么样」分开：目录来自容器自己的索引，内容按需从单个条目解码，两者都不落地。它自己不新增宿主能力，只用既有 SDK 面：`sidebar` 角色、`postTo`/`onMessage`、`call`、`loading`、`status`、`clipboard`。

## 范围与边界

- **不解压**：不写磁盘、不建中间文件、不修改原文件。需要解码的条目在内存中按范围读取，单条目上限见下表；清单只申请 `clipboard`。
- **只读**：预览不提供编辑、转换或另存；需要取出内容时用宿主的「在默认应用中打开」或解压工具。
- **单层**：压缩包内的压缩包只显示事实与提示，不继续展开。
- **不输入密码**：加密条目的名称、大小照常列出，读取时给出明确提示。
- **分卷**：`.part1.rar` 一类只有一个分卷时仍列出目录，读取被拒绝并说明原因。

## 容器与解码

后缀只用于筛选候选，实际格式以文件头为准，因此改名的压缩包按其真实格式读取。

| 容器 | 后缀 | 目录来源 | 条目读取 |
|---|---|---|---|
| zip 及其派生 | `zip` `zipx` `jar` `war` `ear` `aar` `apk` `xpi` `crx` `vsix` `nupkg` `whl` `epub` `cbz` `ipa` `kmz` | 中央目录，不读载荷 | 按条目从头解码，随机访问 |
| 7z | `7z` | 头部的文件表 | 按流解码，整条目入内存 |
| rar | `rar` `cbr` | 头部 | 顺序走到目标条目，整条目入内存 |
| tar / tar+编解码 | `tar` `gz` `tgz` `taz` `bz2` `tbz` `tbz2` `tb2` `xz` `txz` `zst` `tzst` `lz4` `tlz4` | 顺序读头部；压缩流需解压一遍 | 顺序解压到目标条目，按需读前缀 |
| 单文件编解码 | 同上（内层不是 tar 时） | 单条目，名称取 gzip 头记录的名字或去掉后缀的文件名 | 从流开头解压到所需位置 |
| Windows 压缩包 | `cab` | 文件夹与文件表 | 按文件解码，随机访问 |

顺序解码的容器在会话内保留一份已解码前缀，后续范围请求只延长它，不重复从头解码；切换条目即丢弃。

## 原生协议

宿主把 `session`、`path` 与 `settings` 随请求下发，与[原生进程协议](../plugins.md#原生进程协议)一致。

| 方法 | 参数 | 返回 |
|---|---|---|
| `open` | `session` `path` `settings` | 概要 + 第一页条目，见下 |
| `page` | `session` `offset` `limit`（≤2000） | `{total, entries}` |
| `read-entry` | `session` `index` `offset` `length`（≤4 MiB） | `{data(base64), size, eof}` |
| `release` | `session` | `null`，丢弃会话缓存 |

`open` 的概要字段：`format`（`zip`/`7z`/`rar`/`tar`/`gz`/`bz2`/`xz`/`zst`/`lz4`/`cab`）、`codec`、`count`、`files`、`folders`、`bytes`（解压后总量）、`packed`（各条目压缩后之和，未知为 0）、`archiveBytes`（文件本身大小）、`encrypted`、`truncated`、`entries`（首页）。

条目字段：`name`（`/` 分隔，去掉 `./`、开头与结尾的 `/`）、`dir`、`size`、`packed`、`modified`（Unix 秒或 null）、`encrypted`、`method`（`deflate`、`lzma2`、`gzip`、`stored`…）。读取位置是插件的内部信息，不下发。

上限：`open` 首页 1000 条；`page` 每页最多 2000 条；单次读取 4 MiB（base64 后约 5.3 MB，留在宿主 8 MiB 消息预算内）。**这些上限只约束一次读取带回来多少内容，不约束目录与大小**：列表列全，条目大小按容器记录的显示，页请求只是把一次响应切小。图片与文本的读取上限（设置项的 `textLimit`／`mediaLimit`）同样只决定「预览读到哪」，被截断时界面在状态行或 `#notice` 里说明。

目录本身没有产品意义上的条数上限；只有一个防损坏的安全阀：头部谎报上百万条目时在 1 000 000 条处停下并置 `truncated`，界面说明目录被截断。真实的压缩包（包括机器生成、几十万文件的）都完整列出。

单条目进内存的上限是 96 MiB，它由解码方式决定：zip、cab 与 tar 按范围解码，只受当次读取量约束；7z 从块首解码到所需位置即停；rar 的参考解码器只能整条目交出，因此超过 96 MiB 的条目在该格式下无法预览（目录、大小与其余条目不受影响）。

`eof` 由**短读**判定：返回的字节少于请求长度即视为条目结束。单文件编解码的条目大小可能未知（为 0），界面按未知显示，不据此提前结束读取。

### 失败措辞

**打开失败**由宿主直接显示，所以 `open` 返回完整句子，并指明识别到的格式，例如 `notes.zip could not be read as a ZIP archive: …`。**读取失败**发生在视图已经挂载之后，返回 `token` 或 `token:detail`，由视图按当前界面语言成句：

| token | 含义 |
|---|---|
| `password-protected` | 条目已加密，需要密码 |
| `entry-too-large:{size}` | 条目超出可预览上限 |
| `unsupported-method:{method}` | 压缩算法不支持 |
| `entry-missing` | 索引与目录不一致 |
| `entry-is-a-directory` | 请求落在目录条目上 |
| `multipart-archive` | 分卷不完整 |
| `archive-corrupt:{detail}` | 数据无法解码 |
| `io:{detail}` | 文件本身读取失败 |
| `archive-session-expired` | 会话已被回收，重新打开文件 |

词汇表由 `tests/archive-preview.test.mjs` 两侧对齐：原生能报出的每个 token 都必须在视图里有对应文案，视图里也不留没有来源的分支。

## 界面归属

| 界面 | 槽位 | 内容 |
|---|---|---|
| 文件列表 | 侧栏（`sidebar(true, {side:"left", width:260, minWidth:180, maxWidth:420})`） | 目录树、筛选框、排序选择、关闭按钮 |
| 条目内容 | 主视口 | 图片、文本、视频首帧、事实卡与十六进制，加一条压缩包概要空状态 |
| 压缩包与条目事实 | 浮层（`overlay` 300×272） | 概要、压缩比、当前条目字段 |
| 一行状态 | 宿主信息栏（`status()`） | 条目路径、大小、存储方式；未选中时是格式、条目数、解压后总量 |
| 工具按钮 | 宿主工具栏（`controls()`） | 文件列表开关、信息开关、适应窗口（仅图片与视频）、复制压缩包内路径 |

侧栏是次要挂载：不声明控件与状态行，只读文件、调用方法与转发消息；关闭它自己用 `sidebar(false)`，并先告诉视口，使工具栏按钮与实际显示一致。主视图同一时刻只有一个条目在渲染，切换条目先卸下上一个（对象 URL、文本视图与视频元素一并释放）。

### 侧栏与视口之间的消息

宿主只转发不解析；每条消息仍在 64 KiB 预算内，因此目录按编码后大小切成 ≤24 KiB、≤512 条目的批（条目名截断到 512 字节）。

| 方向 | 消息 | 含义 |
|---|---|---|
| 侧栏 → 视口 | `list-hello` | 刚挂载，请下发目录 |
| 视口 → 侧栏 | `list-start` / `list-batch` / `list-end` | 目录批次，`count` 为总数，`truncated` 说明目录被截断 |
| 侧栏 → 视口 | `select` `index` | 选中某个文件 |
| 侧栏 → 视口 | `select-folder` `path` | 选中某个文件夹（视口按路径查自己的树） |
| 视口 → 侧栏 | `selected` `index` | 当前选中项，用于高亮与展开祖先 |
| 侧栏 → 视口 | `list-closed` | 侧栏自己关闭了 |
| 浮层 → 视口 | `info-hello` | 浮层刚挂载，请下发概要 |
| 视口 → 浮层 | `archive-info` | 概要 + 当前条目字段 |
| 浮层 → 视口 | `info-closed` | 浮层自己关闭了 |

## 条目呈现

- **图片**：按 `mediaLimit` 读取（图片自身的 `size` 更小时以它为准），拼成 `Blob` 交给 `<img>`；解码失败显示事实卡而不是空白。动图按图片呈现，动画由浏览器负责——本插件不做播放器。
- **文本**：导入共享文本视图，`textLimit` 决定读取量，`wrap` 设置决定折行，UTF-8／UTF-16 按 BOM 解码；被截断时在共享外壳的 `#notice` 里说明。扩展名没有结论的条目先嗅探前 4 KiB：像文本就走文本视图，否则十六进制。
- **视频**：只取首帧。按 `mediaLimit` 读取后交给一个不可见的 `<video>` 解码，候选时间点依次为 0、0.1、0.5、1、2 秒（按 `duration` 裁剪；`duration` 未知时全试，为 0 时只试 0），整帧同色视为空白帧继续往后试；画面画到最长边不超过 1280 的 canvas 上。编码不受浏览器支持时给出提示，不等待、不重试。`<video>` 只作解码器：它带退出系统合成平面的样式（`tests/host-chrome.test.mjs` 钉住），并且条目切换或视图卸载时被移除。
- **文件夹**：文件数、文件夹数与合计大小。
- **音频、嵌套压缩包**：事实卡 + 一句说明。
- **未知类型**：先嗅探，否则十六进制（最多 4 KiB）+ 事实卡。

## 设置

| key | 类型 | 缺省 | 作用 |
|---|---|---|---|
| `showList` | bool | 是 | 打开压缩包时显示文件列表侧栏 |
| `sort` | select | `name` | 名称／大小／压缩后／修改时间；侧栏的下拉写的是同一份存储 |
| `foldersFirst` | bool | 是 | 每一层先列文件夹 |
| `wrap` | bool | 是 | 文本条目折行 |
| `textLimit` | number | 512 KiB | 文本条目一次预览读取多少内容 |
| `mediaLimit` | number | 48 MiB | 图片与视频一次预览读取多少内容 |

两个读取上限只影响预览：目录、文件数、条目大小与压缩比都来自容器的记录，不随它们变化。上限调大时同一个条目会读得更多，调小只影响后续渲染。

侧栏下拉与设置页显示的是同一个设置项：侧栏用 `setSetting()` 写入，宿主校验并持久化后再以 `onSettings` 回报，两处永远一致。`sort` 的选项文案在清单的 `i18n` 与插件自己的语言表里各写一份（宿主画宿主翻，插件画插件翻），由 `tests/archive-preview.test.mjs` 钉住两边相同。

## 已知边界

- 只保证浏览器能解码的图片与视频：`mkv`/`avi`/`wmv`/`flv` 等容器、以及 WebView2 没有的编码不显示画面，只给提示。
- `.ts` 归代码而不是视频（TypeScript 更常见），`m2ts` 等后缀按视频处理。
- 读取上限是按解码方式施加的：zip、cab、tar 与 7z 只解码到所需位置，条目再大也能预览开头；rar 的参考解码器整条目交出数据，超过 96 MiB 的条目在该格式下无法预览，目录与其余条目不受影响。
- 目录只在容器谎报上百万条目这一种情况下被截断（`truncated`），正常压缩包（含几十万文件）完整列出。
- 单文件编解码的条目大小可能未知：gzip 的尾部长度的可信范围有界，其他编解码一律显示未知。
- 压缩比按「各条目压缩后之和 ÷ 解压后之和」计算；容器自身开销不计入，顺序解码的容器没有逐条目压缩后大小时用文件大小。

## 验收

1. 空宿主打不开 `.zip`；安装后能打开；禁用后新的打开请求失败；慢加载期间切到别的插件后能切回；闲置后进程退出；重新打开可重建。
2. 目录树：隐式文件夹（压缩包没有目录项）、`a\b` 反斜杠、`./` 前缀、重复目录项、空压缩包、只有目录的压缩包都显示正确。
3. 条目预览：图片、文本、二进制、目录、音频、嵌套压缩包各有对应呈现；加密条目给出明确提示而不是空白。
4. 排序与筛选：四种排序、文件夹优先、筛选命中自动展开到命中项。
5. 侧栏：宽度可拖动并记忆；关闭后工具栏按钮同步熄灭；窄窗口下侧栏不超过一半宽度。
6. 视频：mp4/webm 显示首帧；不支持的编码给出提示且不卡住；切换条目后 `<video>` 元素被移除。
7. 主题与语言：浅色／深色下滚动条与共享文本视图一致；切换语言后列表、状态行、浮层与工具栏文案全部更新。
8. 门禁：`cargo test -p ember-archive-plugin`、`node --test tests/archive-preview.test.mjs`、`npm run check` 全部通过；完整 Windows 交互按[测试分层](../testing.md)手工确认。
