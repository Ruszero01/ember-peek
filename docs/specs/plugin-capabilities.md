# 插件能力、共享源与槽位协议

状态：0.1.0 基线。包版本 0.1.0，插件协议 `api:1`。基线协议就是这里定义的这一套，没有更早的字段兼容分支——清单的 `view` 字段已被 `capabilities` + `entry` 取代，旧写法不再接受。

## 决策

一个文件形成一个 `fileId`，其中每个匹配插件都有自己的贡献实例 ID、原生状态、网页入口、控件和错误——**没有插件能独占一个扩展名**，匹配同一格式的插件并存。切换视口仅选择贡献 ID，不重新解析、重开进程或重新挂载已就绪网页。

源选择与视口选择分离：宿主按插件声明的数据契约共享解析结果，不理解正文、像素或网格，也不把消费者绑定到某个插件 ID。基线的源仍可以同时提供预览视口；消费者与源是独立包。

## 清单

```json
{
  "api": 1,
  "id": "example.text-tools",
  "name": "文本工具",
  "version": "0.1.0",
  "extensions": ["txt", "md"],
  "icon": "file-text",
  "executable": "bin/example.exe",
  "entry": "ui/index.html",
  "capabilities": ["view", "controls"],
  "consumes": "ember.text/1",
  "activation": { "mode": "manual", "priority": 0 },
  "permissions": ["writeFile", "clipboard"]
}
```

**清单拒绝未知字段**：`deny_unknown_fields` 是这条基线的一部分，写错的键会让包加载失败并报出字段名，而不是被静默忽略。

| 字段 | 规则 |
|---|---|
| `api` | 必填，本基线为 `1`；不等于宿主支持的版本即拒绝加载 |
| `id` | 必填，≤80 字节，只用小写字母、数字、`.`、`-`（如 `ember.text`），同一宿主内唯一 |
| `name` | 必填，界面显示名 |
| `version` | 必填 SemVer。**市场按它提示更新**：只有远端版本更高才告诉已装用户“有更新”，安装器拒绝降级；`buildId` 用于包身份与开发同步。插件自己维护，不随宿主版本走，native crate 须声明同一个号（打包时校验） |
| `executable` | 必填，包内原生程序路径（如 `bin/ember-text-plugin.exe`） |
| `extensions` | 可选，≤256 项、每项为纯字母数字；不区分大小写；省略、空数组、含 `all` 或 `*` 匹配全部文件，包括无扩展名文件 |
| `fileNames` | 可选，≤128 项、每项 ≤128 字节且不含路径分隔符；精确文件名匹配（忽略大小写），用于 `Dockerfile`、`LICENSE` 这类没有扩展名或扩展名与实际内容无关的文件 |
| `icon` | 可选，宿主图标集里的名字，≤40 字节；未知名字退回通用图标而不是失败 |
| `capabilities` | 必填、不重复；`view` 分配可切换主视口，`overlay` 分配宿主浮层，`controls` 分配功能气泡；`view` 与 `overlay` 可同时声明（同一 entry 挂载两次，用 `role` 区分） |
| `overlay` | 声明 `overlay` 能力时必填，且只在该能力下合法：`{width, height, anchor?}`，宽高是插件内容区的 CSS 像素（不含宿主 12px 拖动条），宽 120–1600、高 24–1200；`anchor` 取 `topRight`（默认）/`topLeft`/`bottomRight`/`bottomLeft`，只决定首次出现的位置 |
| `prepare` | 可选，`true` 表示插件参与**准备阶段**（见「准备阶段」一节）：宿主把预览窗口建好但不显示，等这个插件的视图汇报就绪或声明它需要的东西之后再显示，所以窗口不会先以一个尺寸出现、再在用户眼前改变。只在同时声明 `view` 时合法 |
| `entry` | 必填，包内 HTML 入口；只提供 controls 的插件也用隐藏入口运行自己的按钮逻辑 |
| `activation` | 可选，默认 `{mode:"auto",priority:0}`；auto 自动进入，manual 点击进入；用户通过自动激活开关覆盖模式，通过左侧插件列表拖动排序覆盖优先级 |
| `settings` | 可选，≤32 项；字段与校验见[插件开发](../plugins.md#插件设置) |
| `provides` | 可选，原生解析源产出的契约标识；例如 `ember.text/1` |
| `sourceMethods` | 可选，≤32 项，provides 插件显式导出的源 RPC 方法名；默认空，不会暴露全部原生方法 |
| `consumes` | 可选，消费同一标识的共享数据；不能与 provides 同时声明 |
| `permissions` | 默认空；`readFile` 授权网页读取当前文件，`readResources` 授权网页按文档引用读取本地关联文件或公开 HTTP(S) 资源，`clipboard` 授权网页复制，`openLink` 授权网页把用户点到的链接交给系统打开（宿主只接受 `http`、`https`、`mailto`），`writeFile` 授权通用修改通道 |
| `targets` | 可选，≤8 项，形如 `windows-x86_64`（小写）；省略表示不限制平台 |
| `revision` / `buildId` | 安装期字段，插件源码不写：`revision` 由安装器赋值（打包时写 `0`），`buildId` 由打包脚本从内容算出 |

同一个插件可以同时声明 `view` 和 `overlay`：那是同一个 `entry` 挂载两次，主视口一次、浮层一次，网页用 `ready` 载荷里的 `role` 决定这次画什么。只声明 `controls` 也可以。需要两个互不相干的解析实现时仍应拆成两个插件并消费同一契约，不把解析复制过去。

主视口按优先级从高到低选择自动进入的插件，同优先级按 ID 排序；同类自动插件之间保留按扩展名记录的选择。没有自动进入的 view 时，回退到可用的手动 view，因此仅安装编辑器也能直接打开文件。修改激活设置会清除旧视口偏好，下一次打开生效，不打断当前加载或未提交变更。激活表示前台视口选择，不表示取消其他插件的后台初始化。

视口入口与底部功能气泡合并：点击插件名称切换视口并点亮气泡；点击插件控件先聚焦该插件再执行操作。**只有当前插件的功能按钮展开**，其余气泡只留名称，切换时以宽度动效过渡，因此同时匹配同一文件的插件再多也不会把功能栏撑乱。同时有视口和浮层的插件，气泡负责切换视口，浮层由插件自己开关；只有浮层的插件，气泡开关浮层。自动进入的浮层初始最多展开三个。没有控件的 view 仍有可点击的名称入口。气泡聚焦只高亮插件标题，容器保持中性背景，避免覆盖功能按钮自身的激活状态。

主视口同一时刻只挂载当前插件的网页，切换视口即卸载上一个、挂载下一个，插件网页不应假设自己一直存活。唯一例外是声明了未提交变更的会话，它的网页必须保持挂载，否则变更会随卸载丢失。

浮层是一张独立卡片，宿主只提供一条 12px 拖动条和位置保存：拖动条可自由定位，双击恢复默认位置，按插件记住相对位置，窗口尺寸改变时仍留在可用区域内。标题、按钮、搜索框等内容全部由插件自己绘制在 iframe 里，插件不能决定宿主页面的绝对位置。浮层只在打开时挂载，关闭即卸载；在此之前插件仍可继续原生解析。设置窗口不创建这些网页。

每插件的控件 ID 在自己的贡献实例中隔离，宿主只转发控件 id、不解释语义。禁用、卸载的贡献从可用槽位与气泡移除；有未提交变更的插件拒绝停用或卸载。

一个插件同时有视口和浮层时，两个挂载是两个文档，插件内部通信经宿主的 `peer` 通道转发：宿主只搬运不解析，并在对端未挂载时如实回报 `false`。

## 一个解析源，多份界面

打开文件时收集全部已安装、已启用、匹配类型的包，并固定这次文件会话的版本集合。基线按优先级降序、ID 升序选择一个声明 provides 的包作为源；这只是源提供者的默认决策，不是对所有界面插件的独占决策。相同契约的其他提供者也消费已选源，不重复解析。

1. 源的 `open` 收到 `source:null`，负责解析一次，并保留后续 RPC 需要的原生数据。
2. 不依赖源的文件工具立即独立启动，不等待慢解析器。
3. 消费者等待源 ready，然后收到 `source:{id,contract}`。消费者的 open 用于初始化自身状态，不再次读取文件做同一份解析。
4. 消费者网页的 `ready` 包含自己的 `data`，以及 `source:{contract,data}`；source.data 来自源唯一保存的结果。源选择不会随视口切换改变。
5. 大型数据应由源返回索引或不透明句柄。消费者使用 `sourceCall(method,value)` 请求源在 sourceMethods 中显式导出的分页、网格块等数据。宿主只转发，不解释契约正文。

没有 provides 的文件工具组合可以只使用元数据或已声明的分段字节读取，不强制启动一个虚假的格式解析器。缺少 consumes 所需契约、存在不兼容契约、源失败时，相关贡献显示明确错误；独立工具继续工作。一个文件会话不自动再启动第二个不同契约的解析器。

共享保证是“原生解析一次、切换不再解析”，不是跨 iframe 零拷贝：向网页传输 JSON 仍会序列化和复制。文本基线采用小型 JSON 契约；FBX/PSD/PDF 大型契约应自行设计分块 RPC，不能把整个模型塞入 open 响应。原生源崩溃后的状态恢复由契约实现负责。

## 界面归属：视口只放渲染内容

**视口里只有渲染内容和样式。** 工具按钮、文件名与统计、进度条、音量、“沉浸”用的自绘浮层都不属于视口，各有宿主槽位：

| 这个 UI | 去哪里 |
|---|---|
| 文件名、大小、分辨率/进度这类一行状态 | 宿主左下角信息栏（`status()`） |
| 结构化或持续更新的统计（码率曲线、节点数……） | 自建统计浮层（`overlay`），位置与拖拽由宿主负责 |
| 工具按钮（导出、缩放、开关……） | 右下角工具栏（`controls()`），没有视口时可用的按钮也一样放这里 |
| 需要持续操作的控件（拖动进度条、音量、取色器……） | 自建功能浮层（`overlay`），由工具栏上的一个控件开关（`panel()`） |

还有一类属于渲染内容：**跟着内容滚动、只作用于它所在的那一小块内容**的操作，例如 Markdown 代码块的复制按钮、提示块的展开。它不是视口功能栏——没有它那份内容就不完整，位置由内容决定而不是由视口四角决定。

表里没有的是**画面上短暂的状态标记**：拖动或按键时报出的当前值、跳转等待目标时画的加载环。它们不吃指针、没有任何可操作的东西，画的还是这一帧自己的状态，所以属于渲染内容；一旦要写数值、要能点、要一直挂着，就回到上表 —— 进度数字与文件名一样归宿主信息栏，画面本身只说「还没到」。

理由是这份协议里最重要的一条分工：**沉浸模式、两条栏的显隐、浮层的位置与拖拽都是宿主的能力**。插件把自己的 UI 画进视口，就只能自己在视口里实现同一件事——自绘浮层、自己判断何时显隐、自己避开遮挡——于是同一个行为有两套逻辑，而且插件浮层与宿主工具栏是同一套视觉语言，做进视口会和宿主 UI 割裂。所以“沉浸”不是插件要实现的功能，也不该出现在插件描述里：视口保持干净，沉浸由宿主给出。

这条归属也是宿主敢于把**窗口四角**留给自己（沉浸模式下四个浮层组件自己吃指针，落在其上的指针与点击不转发给插件）的前提：按本节归属，视口四角本来就不该有插件的功能操作，两者因此不会冲突。

## SDK 与宿主边界

```js
import { ready, controls, sourceCall, pending, mutate, fileChanged } from './sdk.js';
const { data, source, file } = await ready;
// source?.data 是源共享的契约结果；data 是本插件 open 的结果。
const chunk = await sourceCall('page', { index: 0 });
await pending(true, '未保存的编辑');  // 声明本次会话有未提交的变更，附上给用户看的措辞
const result = await mutate('save', { /* 本插件自己的格式 */ });
await pending(false);               // 只在保存或明确撤销成功后解除
await fileChanged();              // 使旧缓存失效，当前文件仍被选中时重新组合
```

`pending` 是通用变更声明：宿主不知道也不判断变更是什么（文本草稿、裁剪区域、旋转角度都行），只把它当作"不要销毁这次会话"的依据——存在变更时拒绝卸载、停用和替换该插件，不回收它的预览 WebView，托盘退出要求确认，并且所有拒绝都用插件给的措辞（`reason`，缺省时宿主说"尚未提交的变更"）。第二个参数是给用户看的名词短句，会被截断到 60 字。

宿主不实现 save、编码或文本编辑。`mutate` 检查 writeFile 后调用**该插件自己的**原生业务方法。`fileChanged` 不会在用户已经切换文件后抢回焦点；存在其他未提交变更时保留它，不强制重建。

`sourceCall` 只能寻址宿主为当前贡献选择的源，不能由网页传入另一个会话 ID。生命周期方法 open/release/settings 禁止通过自定义 RPC 绕过。数据契约的源方法应是读取接口；格式修改使用自身插件的 mutate 通道。

## 准备阶段

预览窗口从隐藏状态打开时，声明了 `prepare` 的插件在**显示之前**拿到一次准备机会：宿主按用户记住的尺寸把窗口建好（但不显示），视图在这时汇报就绪，或者声明它需要什么。窗口已经显示而用户切换预览时，新视图的首次声明立即调整现有窗口，位置不动；同一会话被用户手动缩放后不重新套用旧声明。今天声明的是**窗口尺寸**，将来同类事实（例如一份文档的首屏尺寸、一个播放器需要的画中画位置）可以沿同一处扩展，因为宿主在这里只搬运、不解释。

- 声明的是**窗口的尺寸**，不是位置：位置始终由宿主决定 —— 用户自己放过的位置就是那个位置，从没放过就居中。插件既改不了位置，也改不了"用户记住的尺寸"。
- 声明过的尺寸是**临时尺寸**：它只决定这次打开时的窗口，不会写进用户记住的那一份。所以先看一张竖图（窗口变窄）、再看一张横图（窗口按用户自己的尺寸重新算），不会一次比一次窄。
- 宿主只**约束**这个尺寸：装不下屏幕就按同一比例缩小，低于宿主能建的最小窗口就抬到下限（此时形状不再成立，插件应当把内容装进窗口而不是铺满）。
- 宿主与插件的信息是单向补齐的：宿主把**用户记住的窗口尺寸**交给视图（`hostWindow().width` / `.height`），与上一次插件造成的临时尺寸分开；同时提供当前实际尺寸（`currentWidth` / `currentHeight`），让视图算出宿主两条栏占的空间。插件据此把内容适配成最终尺寸（`prepare({window})`），宿主拿到最终尺寸后设置窗口再显示。视图看不到自己所在的窗口有多大，所以这些数只能由宿主给。
- 视图没有要声明的东西就照常汇报就绪（`presented()`）—— 宿主等到两者之一就显示窗口，不会为它多等。

准备阶段要在**用户看到窗口之前**结束，所以插件在这里做的事必须便宜：读一个文件头、问一次自己的原生进程（`call()`），不要把整份内容解码。宿主另有兜底计时器，等不到就按用户记住的尺寸显示窗口。

权限约束作用于网页桥；原生可执行程序仍是用户权限下的可信程序，不是 OS 沙箱。不能把声明当作原生程序的强制文件系统隔离。

## 生命周期与配额

- 缓存键：规范路径、文件大小、修改时间、所有匹配包的安装目录；view 选择不进入缓存键。安装目录在一次安装的生命周期里是稳定的（覆盖更新沿用同一个目录名），所以在换掉目录内容之前会先丢掉该插件的会话。
- 已完成的文件按最近使用顺序保留 4 组；最多 16 个文件会话、每文件 32 个插件、全局 64 个贡献实例。只有受保护的加载或未保存编辑占满硬上限时才提示，不静默遗漏插件。
- 每包版本一个独立原生进程，同进程通过请求 ID 多路复用；每贡献最多 8 个业务调用，单条消息最多 8 MiB，调用超时 120 秒。
- 当前文件的所有贡献，以及存在调用或未提交变更的整个文件组，均保留共同源。加载任务由 Rust 运行时持有，前端切换或关闭不取消。完成的后台文件超过 4 组时按上次打开或选择的时间替换，源与消费者一起释放。
- 最近 4 个视图中尚未汇报 `presented()` 的后台视图继续挂载，让大文件在切换后完成加载；完成后即可卸载其网页，未保存编辑的网页继续保留。更早的未完成网页可以卸载，其原生加载任务仍受保护。
- 120 秒闲置回收仍负责清理剩余无引用会话；最后一个引用释放后关闭包进程。
- 隐藏预览且没有未提交变更时才允许销毁 WebView。存在变更时保留网页里的编辑状态；托盘退出需要确认丢弃。开发后端重启、网页重载和崩溃不承诺变更恢复。
- 安装、启用或更新后，下一次打开文件重新收集贡献集合。更新是覆盖安装：先停掉该插件的原生进程、丢掉它与同批文件的会话，换装后按原路径重开预览，所以磁盘上每个插件只有一个目录；存在未提交变更时更新被拒绝，不会为了换装丢掉用户没保存的东西。停用/卸载立即移除可用 UI，正在执行的任务仍可完成。

## 文本基线

`ember.text`（纯文本）、`ember.code`、`ember.markdown` 与 `ember.text-editor` 都声明 `provides:"ember.text/1"`，各自提供视口。三个预览默认自动进入、优先级 100，编辑默认点击进入、优先级 0。安装其中一个预览与编辑器时共享一次解析；只安装编辑器时，由编辑器自己解析并直接进入编辑视口。解码代码位于插件侧共享库 `crates/text-document`，宿主和运行时不依赖该库。

契约字段：`text`、`encoding`（UTF-8/UTF-16LE/UTF-16BE）、`bom`、`truncated`、`editable`、原始字节 SHA-256 `fingerprint`。不截断且编码有效时允许编辑；混合换行的编辑视口保守地只读。统一 LF/CRLF/CR 换行在编辑视口里规范化为 LF，保存时恢复原换行格式。内容与编码后字节均限制 2 MiB。

存在共享源时编辑插件不进行第二次解码。保存先校验原始指纹，写入同目录临时文件并同步，再以 Windows ReplaceFile 替换原文件，保留其 ACL。写入阶段不截断原文件；只读、共享冲突或检测到外部变更时拒绝保存并保留草稿。句柄阻止并发原位写入，替换前再次检查路径内容；操作系统没有“按内容比较并替换”原语，其他程序在最终检查后同时原子替换路径仍存在极小竞争窗口。

Ctrl+S 保存成功会刷新共享源并保持编辑视口；撤销恢复已保存正文。保存冲突或失败保留编辑草稿，关闭窗口不隐式保存。文本能力分为纯文本、代码、Markdown 预览及文本编辑四个插件，共享行号、高亮和阅读位置，详见 [文本插件族](text-plugins.md)。

`ember.metadata` 省略 extensions，声明 overlay + controls，对任意文件显示元数据，用于验证默认全类型匹配、浮层与功能气泡。宿主中没有对应格式分支。

## 验收

1. 从插件源安装文本预览、文本编辑、文件信息。打开 txt，应出现三个功能气泡和文件信息浮层标题；点击文本预览、文本编辑气泡直接切换并高亮，无顶部视口切换器。
2. 修改编辑内容，来回切换视口，草稿保留；原生源不重新 open。Ctrl+S 后切回预览，正文更新。
3. 分别检查 UTF-8 BOM、UTF-16 LE/BE、LF/CRLF/CR。混合换行、截断文本、非法编码禁止覆盖。
4. 编辑后用外部程序修改文件，保存必须报告冲突，不覆盖磁盘新内容；草稿仍能复制。
5. 拖动浮层位置并重启窗口，位置仍被记住；双击拖动条恢复默认位置（默认位置由宿主视口矩形内缩 16px 得出，普通模式即站在标题栏与功能栏之间），不影响主视口、其他控件或原生加载。浮层始终在插件内容与宿主功能条之上，拖到窗口边缘也不被裁切，也不受插件自己的边缘渐变影响。仅安装文件信息时，任意扩展名和无扩展名文件也能打开工具组合。
6. 将一个示例清单改为 controls-only，只有气泡，没有主视口或浮层。两个插件使用同名控件仍分别路由。
7. 隐藏带草稿的窗口超过 2 分钟，再打开原文件，草稿仍在；未保存时停用/卸载编辑插件被拒绝。
8. 禁用一个无草稿 view，其他视口继续可选；破坏一个插件的 native open，不阻止独立贡献。缺失数据源只报相关依赖错误。
9. 只安装文本编辑，打开文本直接进入编辑；安装文本预览后默认进入预览。修改激活模式和优先级，下一次打开遵循设置且不取消后台加载。
10. 关闭所有干净窗口，等待闲置回收，再用 Explorer 空格恢复。桌面热更新命令仍为 `npm run dev`。
11. 覆盖安装：改一行插件源码并重建，宿主应停掉该插件、把新包换进同一个安装目录、自动重开被切断的预览（目录名不变，`buildId` 变化）；编辑插件里有未保存内容时，更新被拒绝，提示带文件名与插件给的措辞。

回归用例位于 `crates/runtime/tests/lifecycle.rs` 与 `market.rs`（真实子进程），清单与设置校验在 `crates/runtime/src/manifest.rs` 的单元测试里，前端协议与打包器在 `tests/*.test.mjs`。编译检查与实际 Windows 交互验收分开记录；手工步骤见 [Windows 桌面](../windows-desktop.md)。

相关：[架构](../architecture.md)、[插件开发](../plugins.md)、[Windows 桌面](../windows-desktop.md)、[文本插件族](text-plugins.md)。

设置侧栏的插件排序由宿主处理：使用左侧手柄捕获指针，预览保持列表项外观并限制在列表范围，其他项动态让位；松手后持久化完整顺序，取消不保存。键盘方向键排序仍可用。

设置侧栏中启用插件正常显示名称与图标，停用插件弱化名称与图标并独立显示「已停用」标签；状态不影响打开配置与拖动排序。
侧栏插件名称使用可收缩列，序号与停用标签使用独立固定列；长名称省略显示，悬停可读取完整名称。

插件列表工具栏不提供手动刷新按钮；安装、卸载及启停操作完成后自动更新列表。

## 插件快捷键声明

插件就绪后通过 SDK `shortcuts([{id,key,allowInInputs?,repeat?,run}])` 声明命令快捷键，
宿主校验声明并统一绑定；再次声明替换该挂载的列表，空数组注销。快捷键回调与工具栏回调独立。
输入框和重复键默认跳过，按需显式开启；中文输入组合、已被控件处理的事件不触发。
Escape、Space、Ctrl/Meta+O 保留给宿主，不可由插件覆盖。同一挂载的重复按键和 ID 会拒绝。
只有可见且可交互的挂载接收命令，宿主模态对话框期间暂停；焦点在 iframe 时只绑定该挂载。
连接关闭清除绑定，重连由 SDK 重新声明。编辑器、查找框和控件自身的导航键仍由插件内部控件处理。
宿主只传递不透明命令 ID，不认识保存、跳转等插件业务；此接口是 `api:1` 的增量扩展。
