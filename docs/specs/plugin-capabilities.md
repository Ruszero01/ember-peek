# 插件能力、共享源与槽位协议

状态：0.1.0 初始化基线实现。包版本仍为 0.1.0，API 仍为 1；本次直接重定义基线协议，不提供旧 `view` 清单迁移或兼容分支。

## 决策

原先的“第一个插件独占扩展名”已移除。一个文件形成一个 `fileId`，其中每个匹配插件有自己的贡献实例 ID、原生状态、网页入口、控件和错误。切换视口仅选择贡献 ID，不重新解析、重开进程或重新挂载已就绪网页。

源选择与视口选择分离：宿主按插件声明的数据契约共享解析结果，不理解正文、像素或网格，也不把消费者绑定到某个插件 ID。基线的源仍可以同时提供预览视口；消费者与源是独立包。

## 清单

```json
{
  "api": 1,
  "id": "example.text-tools",
  "name": "文本工具",
  "version": "0.1.0",
  "extensions": ["txt", "md"],
  "icon": "file-text",
  "executable": "bin/example.exe",
  "entry": "ui/index.html",
  "capabilities": ["view", "controls"],
  "consumes": "ember.text/1",
  "activation": { "mode": "manual", "priority": 0 },
  "permissions": ["writeFile", "clipboard"]
}
```

| 字段 | 规则 |
|---|---|
| `extensions` | 不区分大小写；省略、空数组、含 `all` 或 `*` 匹配全部文件，包括无扩展名文件 |
| `capabilities` | 必填、不重复；`view` 分配可切换主视口，`overlay` 分配宿主浮层，`controls` 分配功能气泡；`view` 与 `overlay` 可同时声明（同一 entry 挂载两次，用 `role` 区分） |
| `entry` | 包内 HTML 入口；只提供 controls 的插件也用隐藏入口运行自己的按钮逻辑 |
| `provides` | 可选，原生解析源产出的契约标识；例如 `ember.text/1` |
| `sourceMethods` | 可选，provides 插件显式导出的源 RPC 方法名；默认空，不会暴露全部原生方法 |
| `consumes` | 可选，消费同一标识的共享数据；不能与 provides 同时声明 |
| `activation` | 可选，默认 `{mode:"auto",priority:0}`；auto 自动进入，manual 点击进入；用户通过自动激活开关覆盖模式，通过左侧插件列表拖动排序覆盖优先级 |
| `permissions` | 默认空；`readFile` 授权网页读取当前文件，`clipboard` 授权网页复制，`writeFile` 授权通用修改通道 |

同一个插件可以同时声明 `view` 和 `overlay`：那是同一个 `entry` 挂载两次，主视口一次、浮层一次，网页用 `ready` 载荷里的 `role` 决定这次画什么。只声明 `controls` 也可以。需要两个互不相干的解析实现时仍应拆成两个插件并消费同一契约，不把解析复制过去。

主视口按优先级从高到低选择自动进入的插件，同优先级按 ID 排序；同类自动插件之间保留按扩展名记录的选择。没有自动进入的 view 时，回退到可用的手动 view，因此仅安装编辑器也能直接打开文件。修改激活设置会清除旧视口偏好，下一次打开生效，不打断当前加载或草稿。激活表示前台视口选择，不表示取消其他插件的后台初始化。

视口入口与底部功能气泡合并：点击插件名称切换视口并点亮气泡；点击插件控件先聚焦该插件再执行操作。**只有当前插件的功能按钮展开**，其余气泡只留名称，切换时以宽度动效过渡，因此同时匹配同一文件的插件再多也不会把功能栏撑乱。同时有视口和浮层的插件，气泡负责切换视口，浮层由插件自己开关；只有浮层的插件，气泡开关浮层。自动进入的浮层初始最多展开三个。没有控件的 view 仍有可点击的名称入口。

主视口同一时刻只挂载当前插件的网页，切换视口即卸载上一个、挂载下一个，插件网页不应假设自己一直存活。唯一例外是持有未保存草稿的会话，它的网页必须保持挂载，否则草稿会随卸载丢失。

浮层是一张独立卡片，宿主只提供一条 12px 拖动条和位置保存：拖动条可自由定位，双击恢复默认位置，按插件记住相对位置，窗口尺寸改变时仍留在可用区域内。标题、按钮、搜索框等内容全部由插件自己绘制在 iframe 里，插件不能决定宿主页面的绝对位置。浮层只在打开时挂载，关闭即卸载；在此之前插件仍可继续原生解析。设置窗口不创建这些网页。

每插件的控件 ID 在自己的贡献实例中隔离，宿主只转发控件 id、不解释语义。禁用、卸载的贡献从可用槽位与气泡移除；有未保存编辑的插件拒绝停用或卸载。

一个插件同时有视口和浮层时，两个挂载是两个文档，插件内部通信经宿主的 `peer` 通道转发：宿主只搬运不解析，并在对端未挂载时如实回报 `false`。

## 一个解析源，多份界面

打开文件时收集全部已安装、已启用、匹配类型的包，并固定这次文件会话的版本集合。基线按优先级降序、ID 升序选择一个声明 provides 的包作为源；这只是源提供者的默认决策，不是对所有界面插件的独占决策。相同契约的其他提供者也消费已选源，不重复解析。

1. 源的 `open` 收到 `source:null`，负责解析一次，并保留后续 RPC 需要的原生数据。
2. 不依赖源的文件工具立即独立启动，不等待慢解析器。
3. 消费者等待源 ready，然后收到 `source:{id,contract}`。消费者的 open 用于初始化自身状态，不再次读取文件做同一份解析。
4. 消费者网页的 `ready` 包含自己的 `data`，以及 `source:{contract,data}`；source.data 来自源唯一保存的结果。源选择不会随视口切换改变。
5. 大型数据应由源返回索引或不透明句柄。消费者使用 `sourceCall(method,value)` 请求源在 sourceMethods 中显式导出的分页、网格块等数据。宿主只转发，不解释契约正文。

没有 provides 的文件工具组合可以只使用元数据或已声明的分段字节读取，不强制启动一个虚假的格式解析器。缺少 consumes 所需契约、存在不兼容契约、源失败时，相关贡献显示明确错误；独立工具继续工作。一个文件会话不自动再启动第二个不同契约的解析器。

共享保证是“原生解析一次、切换不再解析”，不是跨 iframe 零拷贝：向网页传输 JSON 仍会序列化和复制。文本基线采用小型 JSON 契约；FBX/PSD/PDF 大型契约应自行设计分块 RPC，不能把整个模型塞入 open 响应。原生源崩溃后的状态恢复由契约实现负责。

## SDK 与宿主边界

```js
import { ready, controls, sourceCall, dirty, mutate, fileChanged } from './sdk.js';
const { data, source, file } = await ready;
// source?.data 是源共享的契约结果；data 是本插件 open 的结果。
const chunk = await sourceCall('page', { index: 0 });
await dirty(true);                // 保护未保存的贡献和整个文件组
const result = await mutate('save', { /* 本插件自己的格式 */ });
await dirty(false);               // 只在保存或明确撤销成功后解除
await fileChanged();              // 使旧缓存失效，当前文件仍被选中时重新组合
```

宿主不实现 save、编码或文本编辑。`mutate` 检查 writeFile 后调用**该插件自己的**原生业务方法。`fileChanged` 不会在用户已经切换文件后抢回焦点；存在其他未保存贡献时保留草稿，不强制重建它。

`sourceCall` 只能寻址宿主为当前贡献选择的源，不能由网页传入另一个会话 ID。生命周期方法 open/release/settings 禁止通过自定义 RPC 绕过。数据契约的源方法应是读取接口；格式修改使用自身插件的 mutate 通道。

权限约束作用于网页桥；原生可执行程序仍是用户权限下的可信程序，不是 OS 沙箱。不能把声明当作原生程序的强制文件系统隔离。

## 生命周期与配额

- 缓存键：规范路径、文件大小、修改时间、所有匹配包的不可变版本目录；view 选择不进入缓存键。
- 最多 16 个文件会话、每文件 32 个插件、全局 64 个贡献实例。超限明确提示，不静默遗漏插件。
- 每包版本一个独立原生进程，同进程通过请求 ID 多路复用；每贡献最多 8 个业务调用，单条消息最多 8 MiB，调用超时 120 秒。
- 当前文件的所有贡献，以及存在调用、未保存草稿或最近使用的整个文件组，均保留共同源。加载任务由 Rust 运行时持有，前端切换或关闭不取消。
- 所有贡献都闲置 120 秒且没有草稿/调用时回收；最后一个引用释放后才关闭包进程。
- 隐藏预览且无草稿时才允许销毁 WebView。存在草稿时保留网页编辑状态；托盘退出需要确认丢弃。开发后端重启、网页重载和崩溃不承诺草稿恢复。
- 安装、启用或更新后，下一次打开文件重新收集贡献集合；现有文件保留当时的包版本，避免更新中途重建未保存编辑。停用/卸载立即移除可用 UI，正在执行的任务仍可完成。

## 文本基线

`ember.text` 声明 `provides:"ember.text/1"`，同时提供文本预览；`ember.text-editor` 也声明同一契约的 provides，提供独立编辑视口。文本预览默认自动进入、优先级 100，编辑默认点击进入、优先级 0。两者共同安装时共享一次解析；只安装编辑器时，由编辑器自己解析并直接进入编辑视口。解码代码位于插件侧共享库 `crates/text-document`，宿主和运行时不依赖该库。

契约字段：`text`、`encoding`（UTF-8/UTF-16LE/UTF-16BE）、`bom`、`truncated`、`editable`、原始字节 SHA-256 `fingerprint`。不截断且编码有效时允许编辑；混合换行的编辑视口保守地只读。统一 LF/CRLF/CR 换行在 textarea 中规范化后，保存时恢复原换行格式。内容与编码后字节均限制 2 MiB。

存在共享源时编辑插件不进行第二次解码。保存由其自己的原生代码编码，在 Windows 独占文件句柄下校验原始指纹，再写入、调整长度并同步；只读、共享冲突、外部变更会拒绝保存并保留草稿。写失败尝试恢复原始字节，并明确报告恢复失败。该基线保存是受保护的原位写入，保留文件身份和 ACL；不承诺断电级原子性。

Ctrl+S 保存成功会刷新共享源并保持编辑视口；撤销恢复已保存正文。保存冲突或失败保留编辑草稿，关闭窗口不隐式保存。文本能力现拆分为纯文本、代码、Markdown 预览及文本编辑，共享行号、高亮和阅读位置，详见 [文本插件族](text-plugins.md)。

`ember.metadata` 省略 extensions，声明 overlay + controls，对任意文件显示元数据，用于验证默认全类型匹配、浮层与功能气泡。宿主中没有对应格式分支。

## 验收

1. 从插件源安装文本预览、文本编辑、文件信息。打开 txt，应出现三个功能气泡和文件信息浮层标题；点击文本预览、文本编辑气泡直接切换并高亮，无顶部视口切换器。
2. 修改编辑内容，来回切换视口，草稿保留；原生源不重新 open。Ctrl+S 后切回预览，正文更新。
3. 分别检查 UTF-8 BOM、UTF-16 LE/BE、LF/CRLF/CR。混合换行、截断文本、非法编码禁止覆盖。
4. 编辑后用外部程序修改文件，保存必须报告冲突，不覆盖磁盘新内容；草稿仍能复制。
5. 拖动浮层位置并重启窗口，位置仍被记住；双击拖动条恢复默认位置（默认位置由宿主视口矩形内缩 16px 得出，普通模式即站在标题栏与功能栏之间），不影响主视口、其他控件或原生加载。浮层始终在插件内容与宿主功能条之上，拖到窗口边缘也不被裁切，也不受插件自己的边缘渐变影响。仅安装文件信息时，任意扩展名和无扩展名文件也能打开工具组合。
6. 将一个示例清单改为 controls-only，只有气泡，没有主视口或浮层。两个插件使用同名控件仍分别路由。
7. 隐藏带草稿的窗口超过 2 分钟，再打开原文件，草稿仍在；未保存时停用/卸载编辑插件被拒绝。
8. 禁用一个无草稿 view，其他视口继续可选；破坏一个插件的 native open，不阻止独立贡献。缺失数据源只报相关依赖错误。
9. 只安装文本编辑，打开文本直接进入编辑；安装文本预览后默认进入预览。修改激活模式和优先级，下一次打开遵循设置且不取消后台加载。
10. 关闭所有干净窗口，等待闲置回收，再用 Explorer 空格恢复。桌面热更新命令仍为 `npm run dev`。

回归用例位于 `crates/runtime/tests/lifecycle.rs`、manifest 单元测试和文本编辑原生测试。编译检查与实际 Windows 交互验收分开记录。

相关：[架构](../architecture.md)、[插件开发](../plugins.md)、[Windows 桌面](../windows-desktop.md)。

气泡聚焦只高亮插件标题，容器保持中性背景，避免覆盖功能按钮自身的激活状态。浮层外壳（一条拖动条）由宿主提供，文件信息内容排版仍由 metadata 插件提供。

## 宿主浮层容器

声明 `capabilities` 含 `overlay` 的插件必须同时声明 `overlay` 尺寸，例如 `"overlay": { "width": 290, "height": 152, "anchor": "bottomRight" }`。宽高单位为 CSS 像素，指插件内容区，不含宿主 16px 拖动条；宽度范围 120–1600，高度范围 24–1200。`anchor` 可选，默认 `topRight`，只决定首次出现的位置。非浮层插件不能声明 overlay 尺寸。

宿主只提供一块可拖动的浮动面板和位置记忆，面板内容（标题、关闭按钮、搜索框、信息文本）全部由插件的 entry 网页自己绘制；宿主不提供标题栏、展开/收起按钮或位置重置按钮。浮层挂载是次要挂载：不能上报 `controls`/`status`，也不能发送 `presented`、`dirty`、`fileChanged`、`returnView`、`mutate`，越权调用被明确拒绝。文件信息插件仅负责内容排版，宿主没有针对它的尺寸分支。
