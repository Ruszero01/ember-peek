# PDF 插件族

状态：0.1.0 初版基线，插件协议 api:1。预览与编辑是两个独立官方包，不在宿主增加 PDF 业务分支。

## 预览与编辑

`ember.pdf` 面向只读预览，使用包内 PDF.js 分段读取并渲染。支持单页、连续阅读，左右翻页、上下滚动；连续模式翻页以短动画跳转。适配窗口默认开启，按最大适配倍率铺满，关闭后显示整页。

`ember.pdf-editor` 是手动激活的独立编辑插件，使用包内 PDFium 原生库。视口只绘制页面及文字／图片的选择区域，修改表单放在宿主浮层，翻页、缩放、保存、撤销、插页、删页等按钮声明给宿主。不会替代默认 PDF 预览。预览插件版本为 0.1.1，编辑插件维持 0.1.0。

预览通过四条读取队列限制 SDK 并发，为宿主生命周期及控件请求保留预算；单次读取失败不阻塞后续队列，终止后不再发出排队读取。预览分块读取允许 PDF.js 单独取消读取器：SDK 已发出的读取可能稍后完成，此时没有接收者的响应须丢弃，不得把它报告为文档加载失败；其他活动读取器继续正常接收。包内 PDF.js 的 `PDFDataTransportStream` 保留这一取消兼容补丁，升级依赖时须重跑分块取消回归测试。

## 编辑基线

- 点击独立文字对象，在浮层修改单个文字片段并应用。使用原字体时修改原对象；清空文字后应用会删除对象。原字体无法表示新文字时拒绝该次修改，草稿不变。
- 可选择 Windows 的 Arial 或黑体（SimHei）字体。更换字体会删除旧对象并创建真正的文字对象，保持字号、颜色和变换矩阵，不覆盖白块、不把旧文字藏在图片下。新对象加入页面内容末尾，复杂重叠排版的叠放顺序可能变化；描边／裁剪文字只允许使用原字体。
- 选择图片后上传 PNG 或 JPEG 并替换原图片对象，保留原对象的位置、大小及变换，图片填入原占位区域。
- 在当前页后插入同尺寸空白页；删除当前页后选择下一有效页，至少保留一页。删除须在宿主模态中确认。初版不导入其他 PDF 的页面。
- 应用修改只更新内存草稿；保存按钮或 Ctrl+S 才写原文件。浮层的保存／Ctrl+S 会先应用当前文字或已选择的替换图片再保存。撤销为草稿操作级撤销，支持最多 20 步、合计 64 MiB 的历史；放弃更改经确认恢复到上次保存版本，保存后清空历史。文字输入框保留浏览器自身的 Ctrl+Z。
- 左右翻页、上下滚动；Ctrl+S 保存，非输入框里的 Ctrl+Z 撤销草稿操作。位置与预览共享，缩放倍率由各自视图管理。

不提供段落自动重排、OCR、表单字段编辑、注释编辑、嵌套 Form XObject 内容编辑或复杂排版保证。扫描 PDF 的文字没有独立文字对象，不能按文字编辑；其独立图片对象仍可替换。只展示独立、可见文字和图片的选择区域，其他页面内容保持渲染并提示存在不可选择内容。

## 不透明共享阅读位置

两包声明 `viewStateContract: "ember.pdf-position/1"`，通过通用 SDK `viewState` / `synchronizeState` 共享 `{page, x, y}`。page 从 1 开始，x/y 是视口起点相对当前页宽高的比例，范围 0–1；接收者校验并按当前页数裁剪。隐藏视图不覆盖位置，显示时先完成恢复。尺寸或阅读模式改变时保持当前位置，零尺寸的隐藏视口不提交状态。保存前提交位置，宿主刷新会话后继续定位正在编辑的页。

位置组与草稿分离，不携带 PDF 字节、图片或文本正文；宿主不理解页码。内存状态跨保存／插件更新的会话重建保留，退出宿主后清空。详见[通用共享视图状态](plugin-capabilities.md#通用共享视图状态)。

## 原生编辑契约

网页 `call` 与 `mutate` 的结果对宿主不透明，原生请求含 session / path / value。`open` 返回 `{revision,pages,page,width,height,dirty,undo,editable}`；width / height 为当前页的 PDF 点数。

`call("state", {})` 返回当前原生草稿元数据，视图重新挂载时先读取它，避免复用最初 open 的过期 revision。页面渲染与编辑操作按序执行。

`call("page", {revision,page,width})` 返回有界 PNG Base64、位图尺寸及独立对象列表 `{id,kind,text,bounds}`，bounds 为位图像素下的 `[x,y,width,height]`。对象 id 只在对应 revision 和 page 下有效，任何修改都使旧对象选择失效。

图片选中后显示四角缩放手柄，拖动时默认独立调整宽高，按住 Shift 等比例预览、对角固定，松开提交一次草稿；Escape 或指针取消不修改文档。缩放修改原有图片对象的矩阵，保留旋转与倾斜、图片像素和对象数量，可撤销，保存后持久化。

草稿 RPC 为 `resizeImage`（object/scaleX/scaleY/corner，两轴倍率均为 0.05–20；兼容单一 scale 等比倍率，corner 为 nw/ne/sw/se）、`editText`（object/text/font）、`replaceImage`（object/image）、`insertPage`、`deletePage`、`undo`、`revert`，都须携带 revision / page。应用修改前网页等待 `pending(true)` 成功；原生在临时文档完成操作、生成内容并验证序列化后才提交新草稿。错误不改变旧草稿，错误后仍按实际 dirty 状态报告 pending。缺失的原生会话明确报错，禁止重新读原文件假装草稿仍在。

只有 `mutate("save", {revision,page})` 写源文件，需要 writeFile 权限。保存对照上次保存字节，拒绝外部修改和只读文件，失败保留草稿；用共享文件库原子替换，不截断原文件。成功清除 pending，再调用 fileChanged 刷新其他贡献与共享位置。签名 PDF 或禁止修改／页面重组的 PDF 只读；密码保护 PDF 暂不支持编辑。

## 资源边界

文件及序列化草稿均最多 32 MiB，1–1000 页；单个文字片段最多 4096 UTF-8 字节且不能含控制字符。替换图片最多 4 MiB、4096×4096 像素，仅 PNG/JPEG。页面位图宽最多 1600、高最多 2400，PNG 最多 4 MiB；网页每页最多获得 2000 个可选择对象。原生最多保留 8 个文档，总草稿／历史预算 256 MiB。超限报错，不部分写入源文件。

PDFium DLL 固定为 Windows x86_64 的 156.0.8076.0，来源与 SHA-256 在包内 dependencies.json，发行许可证与依赖许可随包提供；Rust 绑定固定 pdfium-render 0.9.4，避免旧版对象释放缺陷。Windows 字体从系统 Fonts 目录加载，不随插件分发；DLL 与渲染均不依赖网络。

## 验证

原生测试用实际 PDF 对象验证文字替换／删除和中文字体、图像像素与矩阵、页面顺序与最后一页保护、撤销、外部修改冲突、文件锁失败、错误事务与会话释放。网页测试覆盖命令修订号、比例位置、选择区域及图片传输预算。运行中的 WebView 另需验收浮层输入、真实文件选择、快捷键、保存刷新和预览／编辑双向位置切换，见[手动测试矩阵](../testing.md)。
中文字体替换回归测试使用仓库内 Apache-2.0 的最小 CID 测试字体，验证 Unicode 映射、文字提取与对象删除，不依赖 CI 是否安装可选语言字体；正式插件仍从系统 Fonts 目录读取 Arial／黑体。
