# 字体预览

`ember.font` 面向「这个字体长什么样、里面有什么」：视口是一张**字体样本页**（可打字的规范行 + 按字号阶梯排列的同一句话），完整字库在**宿主侧栏**里按 Unicode 区块铺开，另有一个浮层检视单个字形。字体文件很少小，CJK 集合动辄几十兆、几万个字形，所以这份契约的核心是**谁读字节、谁栅格化、什么留在内存里、什么时候才去读字符表**。

## 容器与格式

| 容器 | 文件头 | 解析 | 交给预览引擎 |
|---|---|---|---|
| 单面 sfnt（TrueType/CFF） | `0x00010000`、`true`、`otf`、OTTO | 直接读自身表目录 | 原文件 URL |
| 集合 TTC/OTC | `ttcf` | 按字面索引读该面的表 | 逐字面写出独立 sfnt |
| WOFF | `wOFF` | 逐表 zlib 解压后重建成 sfnt | 原文件 URL |
| WOFF2 | `wOF2` | 单条 brotli 流按需解出解析用表 | 原文件 URL |
| Mac 资源叉 dfont | 资源头 + `sfnt` 资源 | 每个资源是一份独立 sfnt | 该资源写出为 `.ttf`/`.otf` |

后缀只用于筛出候选：扩展名与实际内容不符时以文件头为准；认不出的文件以 `{"applicable": false}` 回报，由宿主把该插件从候选中去掉，而不是显示一个坏掉的预览。

**原生侧只做表级读取**：`head`、`hhea`、`maxp`、`cmap`、`name`、`OS/2`、`post`、`hmtx`、`fvar`、`STAT`。轮廓表（`glyf`、`loca`、`CFF `）不参与解析，因为它们不产生任何界面上的事实：字形由浏览器自己的字体引擎栅格化，插件不需要路径数据。

## 字节的流向

字体字节只有一条离开磁盘的路径：**引擎自己按 URL 取**。网页用 `fileUrl()`（单面容器）或 `resourceUrl()`（原生写出的字面）构造 `FontFace`，于是插件的 JavaScript 堆里从不出现字体字节——一份 17 MB 的 CJK 字体在插件里占用的是零字节，而不是 17 MB 的 `ArrayBuffer` 加一次结构化克隆。视口与字库侧栏是两个文档，各自注册自己的 `FontFace`（同一份字体因此被引擎加载两次，这是两个挂载各自的渲染需要）。

集合与 dfont 必须由原生写出：预览引擎只认单面 sfnt，而集合的字面共享表数据、表偏移相对整个文件，因此原生把该面的表目录重建成一个独立文件（重算表校验和与 `head.checkSumAdjustment`），写进会话临时目录，路径随 `open` 之后由 `face` 方法返回。临时目录在**进程启动时整体清空**（上一次进程是被宿主直接杀掉的，它的字面没人能再要），并在 `release` 时按会话删除；同一个会话最多保留三份写出的字面，按最近使用淘汰。

WOFF 的全部表都会解出：引擎本来能读 WOFF，但万一读不了，这份解压结果就是可以替它显示的那一份。WOFF2 只解出解析需要的表：单条 brotli 流按顺序读、只留下需要的区间、越过最后一个需要的表就停止解码，被变换的 `glyf`/`loca` 直接跳过。**变换过的 `hmtx` 无法在这里还原**（侧边空白要从 glyf 的 `xMin` 反推），此时该面不报步进宽度，界面显示为空而不是编一个数。

## 上限与拒绝

上限一律先看声明、再看实际，超出即拒绝而不是尽力而为：

- 文件 **256 MiB**（读入前判断）
- 单个重建出的 sfnt **512 MiB**（容器头声明的解压总量就按它拦）
- 写出的字面 **64 MiB**（宿主对单个关联资源的上限）
- WOFF/WOFF2 的表数 ≤ 4096、集合字面数 ≤ 4096、表偏移必须在文件内

失败以 `token[:detail]` 回报，由网页按当前界面语言成句：`font-unknown`（不是字体，走不适用路径）、`font-too-large:256`、`font-truncated:…`、`font-broken:…`、`font-collection-count:…`、`font-face-index:…`、`font-container-unsupported:woff2-extract`、`font-session-expired`。`open` 阶段的失败**返回数据而不是错误**，这样视口能自己把句子画出来；只有路径缺失这类内部错误才用 error 通道。

## 什么时候读字符表

**打开字体不读字符表。** 视口只拿两样东西：`details`（名字、度量、可变轴、表清单）和字体本身；打字时用 `covers` 问一行字（≤256 个码位）在不在这份字体里。三万个字符的枚举只发生在有人打开字库侧栏、并且滚到那里的时候。

原生进程内部按面缓存一份字符表（三万码位约 10 ms、200 KB，进程闲置即回收），对外只给切片与查询：

| 方法 | 语义 | 代价 |
|---|---|---|
| `coverage` | 按列表下标取一页（默认 4096 码位），并带上总数与未编码数 | 首次调用构建缓存 |
| `covers` | 一批码位是否在字体里（≤256，直接查 cmap，不建表） | 与列表无关 |
| `rank` | 一个码位在列表中的位置，以及它是否在列表里 | 二分查找 |
| `unencoded` | 未被任何字符触达的字形 id，分页 | 需要列表 |
| `names` | 一批字形名的 `post` 记录（≤512） | 与列表无关 |
| `glyph` | 单个字符：字形号、名字、步进宽度、左旁空白、同形的其他字符 | 与列表无关 |
| `details` / `face` / `open` / `release` | 事实、写出字面、生命周期 | — |

分页传输：每页按序增量编码（每字节 7 位、低位在前、最高位续接）再 base64，一页只在自身内累加，因此网页可以只解一页。字符表覆盖来自 `cmap` 的**全部 Unicode 子表**，合并去重；代理区（U+D800–U+DFFF）不是字符，枚举时丢弃；`covers` 与 `rank` 走解析器自己的字形查找，因此不会因为某种子表格式而漏判。

**未编码字形**＝`numGlyphs` 减去被 `cmap` 触达的字形，排在区块之后，同样按可见行分页读取；字形名来自 `post` 2.0（3.0 与 1.0 不给名字，界面只显示字形号）。

## 界面归属

| 槽位 | 内容 |
|---|---|
| 视口 | 字体样本页：可打字的规范行（度量参考线、缺失字符标注）＋ 字号阶梯 |
| 侧栏 | 字库：按 Unicode 区块分格的虚拟化字符表，末尾接未编码字形 |
| 浮层 | 字形检视：共享搜索条、所选字形的图形与事实、可变轴滑动条、字体事实 |
| 工具栏 | 字库开关（侧栏）、度量参考线开关、字号（数值拖动）、字形检视开关 |
| 信息栏 | 「字符数 · 当前码位」一行（字符数在字库打开并读到总数后才有） |

### 视口：一张样本页

- **规范行**是 `contenteditable="plaintext-only"`，用被预览的字体绘制；字体缺失的字符用 CSS Custom Highlight 标注，不改动文本节点（包裹字符会和光标打架）。缺失与否由 `covers` 回答，不依赖任何本地字符表。
- **度量参考线**按字体自己的字体单位换算：上伸、大写高、x 高、基线与下伸，字体没声明的值不画；字号小时相邻标线会挤在一起，因此只在有位置的地方写数字，基线永远写。基线位置由**零高内联块实测**——它坐在基线上面，所以它的下边缘就是那一条线，浏览器用什么度量决定行盒都不会看错。
- **字号阶梯**把同一句话按 12/16/22/30/40/54/72 排下来。规范行随工具条字号变化，阶梯固定：两者一起才是一张样本页——大字号看形状，小字号看排版。
- 输入的文字同时进入阶梯；纸张高度随文字生长，整张样本页一起滚动，所以参考线始终落在它标的那一行上。
- 引擎拒绝加载字体时（例如数据不完整），视口**不画替代字体**：说明引擎读不了它。WOFF2 集合里第一个字面之外的成员属于这种情况。

### 侧栏：字库

- **只有打开字库时才读字符表**（设置项 `library` 默认关闭）。侧栏挂载后先读第一页并问出总数，其余部分先按「未读取的字符数 ÷ 列数」占好滚动高度，滚动到附近再读下一页；一直滚到底就按页读到完，然后接着读未编码字形。
- 列表是**字符表的前缀**：只追加、不插入，因此滚动位置与行的地址都稳定；一页若不在队首（例如切换字面时到来的旧页）直接丢弃。
- 只挂载视口看得见的行：一份四万字的字体在文档里始终只有一屏节点。列宽固定（44 px），密度由用户拖动宿主侧栏的宽度决定，宿主按插件与左右位置记住宽度。
- 每个字符格由引擎绘制；**是否有墨水由 canvas 实测一次并记住**（空格、软连字符这类编码了却什么都不画的字符用点线框标出），可变轴改变时这份测量作废重来。
- 顶部一行状态报出当前视口所在的区块与区间，右端同时显示**当前选中的码位**：检视浮层可能被拖到任何位置，而「现在指的是哪一个」应当就在点它的地方读得到。
- 点选一格即选中该字符。

### 浮层的位置

浮层的默认锚点是 **`bottomLeft`**，因为字库侧栏停靠在右侧：点字形会自动打开检视，若默认把它放在右上角，它就会盖住你正要继续点的网格。锚点只在**用户没有拖动过**时生效——拖过一次之后位置由宿主按插件记住（`ember.overlay-positions`），插件不去覆盖用户的选择。所以字库读到为止的信息栏、侧栏顶上那行选中码位，都是为了让「浮层被拖到哪里」不再决定你能不能看清自己在点什么。

### 浮层：字形检视

面板与侧栏是两个文档：字符表与字体在侧栏里，面板通过 `postTo`/`onMessage` 收到侧栏的状态，以及**由侧栏画好并传过去的字形图片**（面板不重新加载字体）。面板自己的字形事实（字形号、同形字符、墨水盒）由它直接问原生。

**在字库里点选一个字形即打开检视**：看一个字形就是检视面板的全部职责，所以选中它就该看见它，不必再去工具栏点一次。这个「打开」由**视口**执行，不由侧栏自己调 `panel()`——工具栏那个开关的状态归视口，面板出现了而按钮没点亮（或反过来）就是两处状态打架。视口只在关着的时候打开，所以用户手动收起后点新字形仍会再开。侧栏顺带把「这份字体有多少字符、当前是哪一个」告诉视口，信息栏因此显示字符数；字库还没读之前显示的是字体自己的字形数，并且标注成「字形」而不是「字符」。

查询按下面三种读法之一解析，然后由侧栏用 `rank` 定位并按需读页：

- **码位**：`4e00`、`U+4E01`（三个以上十六进制位，或写了 `u+`）
- **区块名**：`cjk`、`表情`、`latin-1`（三个字符以上，或两个以上非 ASCII 字符，避免「ab」命中 Arabic）
- **字符本身**：`A`、`永`（逐个查 `covers`，命中的字符按顺序成为匹配项）

上一项 / 下一项在匹配项之间移动，每一步只读它落到那一页。可变轴滑动条同时送到视口与侧栏——轴属于字体，不属于某一个视图。

## 性能预算

| 步骤 | 目标 |
|---|---|
| `open`（含每面名称与表目录） | 十毫秒级，与文件大小无关（只读表目录） |
| 打开字体的字符表读取 | **零**：不枚举，只问一行内的字符 |
| 首屏可交互 | 字体加载完成 + 一次 `details`；不等待任何字符表 |
| 字库首屏 | 一页 4096 码位 ≈ 5 KB base64（Noto Sans SC 约 30,890 字符、8 页） |
| 单页传输 | 4096 码位 ≈ 5 KB base64 |
| 视口内存 | 只存活一屏行；网页侧字符表随滚动增长（三万字 `Int32Array` 120 KB） |
| 引擎侧 | 字体字节不进插件堆；字体由引擎按 URL 加载（每个挂载一份） |

## 手动验收

- 单面 TTF/OTF：打开即出现样本页与字号阶梯，**不打开字库时没有任何字符表读取**（原生方法序列里只有 `open`、`details`、以及打字时的 `covers`）。
- 打字：输入字体没有的字符时下方标出数量并加虚线下划线；输入框与阶梯同步。
- 字号：拖动工具条的字号控件，规范行与参考线跟着变，阶梯不变。
- 字库：打开侧栏才出现内容；第一屏是一页字符，往下滚动逐页补齐；一直拖到底会继续读到完，末尾出现未编码字形；侧栏宽度可拖动，重新打开文件后宽度被记住。
- 搜索：`4e00`、`永`、`cjk` 三种输入都能定位到正确字符；上一项/下一项在匹配项之间移动。
- 字形检视：点选一格后浮层显示该字形的图片与事实（含同形字符），可变轴滑动条改变样本页与字库的字形。
- 可变字体：轴滑动条改变样本页与字库；恢复默认可用。
- TTC/OTC：面切换正确（样本页与字库同时切换）；切换后临时目录出现该面的文件，关闭预览后消失。
- WOFF/WOFF2：字符表与原始 ttf 一致；带 `hmtx` 变换的 WOFF2 不显示步进宽度。
- 引擎拒绝的字体、非字体文件（改名的压缩包）与超过上限的文件各走各的提示，不出现空白视口。
