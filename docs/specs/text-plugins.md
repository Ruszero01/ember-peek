# 文本插件族（0.1.0）

## 独立安装

| 插件 | 适用内容 | 能力 |
|---|---|---|
| ember.text | txt、text、log、csv、tsv、nfo、asc，以及 LICENSE / NOTICE / README / CHANGELOG | 纯文本、行号、换行开关、复制 |
| ember.code | 常见代码与配置扩展名，Dockerfile / Makefile / .gitignore 等文件名 | 按语言语法高亮、行号、换行开关、复制 |
| ember.markdown | md、markdown、mdown、mkd | 渲染/源码切换、共享行号、跟随阅读位置的大纲、点击标题定位 |
| ember.text-editor | 上述文本格式的合集 | 固定自动换行、语法高亮、行号、保存、撤销未保存修改、搜索浮层 |

每个预览插件携带独立原生程序，都能单独安装。编辑器不依赖安装任何预览。所有文本插件使用 `ember.text/1` 数据契约和插件侧 `crates/text-document` 解码库；同文件只选择一个源解码，其他贡献消费结果。纯预览用户无需安装编辑器。

`extensions` 决定扩展名，`fileNames` 可声明精确文件名（忽略大小写），用于无扩展名代码及说明文件。未覆盖的扩展名可由插件清单补充。未知语言使用纯文本高亮回退；不会把二进制格式当作文本编辑器支持范围。

## 共享文本组件

`sdk/web/text/view.js` 使用 CodeMirror 6 实现虚拟化文本视图，统一字体、正文留白、自动换行、语法高亮、搜索匹配与定位。`sdk/web/gutter.js` 是它共享的逻辑行号组件：折行仍属于原逻辑行，编辑、缩放和窗口尺寸变化时自动对齐。`sdk/web/text/navigation.js` 把阅读位置接到宿主的 `viewState` 通道，`sdk/web/text/markdown.js` 提供渲染与大纲解析。四个文本插件导入的是同一份实现，包内没有各自的副本。

宿主负责视口边界及工具栏空间，插件不需要自己预留标题栏或功能栏高度。通用样式使用 `sdk-ui.css`，正文布局来自 `sdk-text.css`，宿主不引入 CodeMirror 或 Markdown 渲染库。

`scripts/build-plugins.mjs` 通过 esbuild 打包插件侧组件，语言语法按需动态加载包内分块，无 CDN 依赖。共享源文件参与构建摘要，所以改一次 `view.js` 会改变每个用到它的插件的 `buildId`，开发宿主随即覆盖安装这些插件——这是刻意的：包内内容变了，包的指纹就应该变。开发监听由 `npm run dev` 统一启动。

## 位置同步

`viewState(value?)` 是通用 SDK 桥。宿主按规范文件路径和声明的数据契约隔离状态，仅保存不透明 JSON；主视口可以读写，浮层不可写。每项不超过 4 KiB，最多保留 128 项，满额淘汰最旧项。不写磁盘，退出应用后清空。

文本族通过 `synchronizePosition` 保存 `{line,column}`，切换插件及保存重建文件会话时恢复。原始文本以逻辑行为锚点，Markdown 渲染视图以对应源码块为锚点；不承诺不同布局之间像素一致。滚动只保存可见视图的位置，隐藏草稿不会覆盖位置。同步的是阅读位置，不传播未保存正文；编辑后应先保存再查看更新的预览。

## Markdown

使用 markdown-it 解析 CommonMark 及内置表格、删除线，DOMPurify 清理生成 HTML；不执行原文 HTML、脚本，不加载文件引用的网络图片，图片显示替代文本。外部链接不会在插件内导航。大纲从解析得到的标题生成，不将代码块中的井号误判为标题；同名标题使用独立锚点。标题定位采用缓存及二分查找，滚动时只更新当前项。

## 边界与手动验收

支持 UTF-8、带 BOM 的 UTF-16 LE/BE；延续 2 MiB 解码限制，截断、非法编码、混合换行保持只读。Markdown 渲染会生成文档 DOM，尚未做块级虚拟化；代码和编辑视图使用虚拟化布局。保存延续编码/换行恢复、SHA-256 外部冲突检查和草稿保护。

1. 分别只安装三种预览中的一种，打开其格式，确认可单独预览。
2. 编辑长行与多行文本，缩窄窗口：固定换行、逻辑行号、高亮和搜索定位一致。
3. 在代码中滚动、切到编辑、修改保存、回到代码预览：恢复对应位置和新正文。
4. Markdown 切换源码/渲染、点击大纲、滚动大纲跟随；重复标题、围栏代码、长表格及脚本文本不破坏定位和安全边界。
5. 打开另一个文件，阅读位置互不污染；仅切换插件不传播未保存草稿。
6. 外部修改磁盘文件后保存应报告冲突并保留草稿；非法编码及混合换行不能覆盖。

上面的步骤在 `npm run dev` 里手动走一遍；自动化测试只覆盖解码、编码、冲突检测与位置同步的可测部分，编译通过不能代替界面验收。
