# 开机自启

通用设置的“启动”卡片提供“开机自启”，默认关闭。它不是一个由应用记住的偏好，而是当前用户注册表里的一个登录启动项：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下名为 `Ember Peek` 的字符串值，内容是当前可执行文件的完整路径，**始终带引号**（默认安装路径里有空格，不加引号的 `C:\Program Files\...` 不是 Windows 能找到的路径）。值名固定：改名会留下旧条目，登录时启动两份。

注册表是唯一存储。设置开关每次都向宿主读回真实状态（`autostart_enabled`），写入（`set_autostart`）之后再读一次并显示读回的值，所以被拒绝的写入会让开关保持原样，而不是停在用户点的那一下。`host-state.json` 与插件运行时都不保存这个值 —— 任务管理器、另一个安装或用户本人都能在应用之外改它，留第二份记录只会和 Windows 的实际行为对不上。

只有指向**当前这个可执行文件**的条目才算已开启：路径比较忽略大小写（Windows 路径就是这样），被移动过的路径、另一个安装、或手工写的其他程序都读作关闭，开关写回时按当前路径覆盖。未加引号的条目按整串比较，因此“路径加参数”不会被误认成本应用。

任务管理器的“启动”页显示并可能禁用同一个条目，禁用状态写在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` 的同名值里。开关**不读**这个值（它是 Explorer 自己的二进制格式），但**打开开关时会删除它**：用户在这里打开就应该真的开机启动，而不是被别处留下的禁用状态悄悄挡掉。删除失败只记诊断，不影响已经写好的条目。

登录启动只拉起托盘进程，不会自己打开预览或设置窗口 —— 窗口仍然按需创建。首次启动尚未回答引导页时，仍然只弹这一次引导页。

非 Windows 平台不支持该设置：读取按关闭处理，写入返回一条明确的不支持提示。

卸载暂不清理这个注册表值（安装包脚本未改），所以卸载后可能留下一个指向已不存在文件的登录项；Windows 会静默跳过它，重新安装到同一路径后该条目继续生效。

实现位于 `src-tauri/src/autostart.rs`（注册表读写与命令），界面在通用设置的“启动”卡片（`src/main.tsx`，“自动更新插件”也在这一卡片）。

自动测试覆盖命令行拼写、“是否指向本可执行文件”的判定（大小写、未加引号、路径带参数）与注册表字符串的字节编解码往返；`tests/autostart.test.mjs` 钉住规范与原生代码指向同一个键和值名、开关显示的是读回的状态而不是点击的值、以及运行时与 `host-state.json` 都不保存这个值。真实注册表的读写留作显式检查：`cargo test -p ember-peek --bin ember-peek -- --ignored`（用测试专用的值名与一个不存在的路径，不会让本应用开机启动）。

Windows 手动验收：打开“开机自启”后，任务管理器“启动”页应出现 Ember Peek，指向当前安装路径；注销或重启后托盘出现且不弹窗口。在任务管理器里禁用该条目后，回到设置里把开关关一次再打开，条目应恢复为启用（开关会清掉那个禁用状态）。关闭开关后条目消失，任务管理器里也不再有它。
