# AI 插件工坊第一版方案

状态：第一版代码已落地，等待真实 API 与桌面交互验收。更新：2026-09-20。

## Agent 工作台修订（2026-09-20）

工坊界面改为常见的 Agent 工作台：左侧是任务列表，中间是模型输出（用户需求与助手回复按轮次排成对话），右侧是独立的「流程」栏（阶段、工具执行记录、token 用量与构建摘要）。模型说的话与任务进度分开呈现，流式文本只更新它自己的那条回复。

- 取消「简单预览 / 详细定制」两种模式，所有任务走同一条链路：用户直接描述需求，需要样例时再附加文件；拖入文件不再注入任何内置需求。此前简单模式会替用户写一段"生成最小只读预览插件"的指令，生成方向由这段内置文本决定，用户真正的需求只在详细模式生效。`Project.mode` 字段随之移除，旧项目记录仍可读取（未知字段被忽略），旧记录里的需求与最后一段模型输出会迁移进对话记录。
- 生成提示词与需求分析提示词只描述宿主与 SDK 的构建规范：api:1 清单字段、SDK 入口与 `ready` 契约、`controls` 声明、只读与离线限制、开发包模块清单。不再点名任何文件格式、解析库或图标示例，不再要求"最小只读视图"。插件方向由用户需求与样例扩展名决定。
- Agent 新增 `list_icons` 工具，从宿主自带的 Lucide 索引取真实名称；此外不向模型开放新的工具或接口。
- 安装状态每次 `state` 查询都以宿主的插件列表为准：在插件管理里卸载后，工坊不再显示"已安装"，并回到可安装状态。
- 任务可删除：删除移除该任务的对话、草稿、全部构建版本与截图，用户自己的样例文件不受影响。已安装的任务先弹确认，可选择保留已安装插件或一并卸载。删除同时关闭该任务残留的试预览窗口。
- 自检闭环（2026-09-20 续）：模型在生成过程中可以调用 `preview`，由宿主构建当前已通过校验的文件、在试预览窗口里用样例运行、等待页面自行回报（`presented` 决定构建是 `ready` 还是 `previewFailed`），并截图存档。返回值包含页面结论、页面自己记录的未捕获错误与 console 报错、以及截图（失败时自动附带）；模型据此在同一次生成里反复修正，直到通过或自检预算用尽（每次运行 4 次、单次 45 秒）。自检通过即记为试预览通过。视图 SDK 因此新增了运行诊断上报（未捕获错误、未处理拒绝、console.error/warn），宿主的窗口实现通过 `ProbeWindows` 抽出来，测试用假窗口驱动整条链路。没有样例文件时不运行，并明确告诉模型"未做运行验证"。
- 生成物自带库（2026-09-21）：模型可写 `ui/` 下任意文件（页面自己的辅助模块）与 `ui/vendor/` 下的库，用相对路径 import；校验规则从"只认开发包清单"改为"import 必须解析到包内文件"，裸包名与远程地址仍拒绝。宿主在保存（多级路径 + 目录创建）、打包（草稿整棵树复制进产物、纳入产物指纹）、展示（「生成文件」列出全部）三处一致。开发包新增"预置库"链路：`sdk/web/` 下的源在构建工坊包时由 esbuild 打包（连许可证一起）进 `ui/`，随 `development-kit.json` 的 `assets` 复制进生成包；首个库是 `psd.js`（ag-psd，MIT）。分发点只有工坊包，生成包各自携带副本，因此导出分享的插件在没有工坊、没有本仓库的机器上也能跑。
- 预置库扩充为 PDF，并按使用取舍（2026-09-21 续）：新增 `pdf.js`（pdf.js 6.3.289，Apache-2.0，1.67 MB），用 pdf.js 自己的主线程路线（`globalThis.pdfjsWorker`）把解析器带进同一个模块——预览页是沙箱文档，只能起 blob worker、不能取脚本，pdf.js 默认的独立 worker 在那里没有来源。选 legacy 构建是有意的：预览页跑在机器上现装的 WebView2 里，当前构建依赖较新的引擎特性（已实测在其缺失时直接抛错），legacy 自带 polyfill。模块导出 `openPdf`（`isEvalSupported:false`，关掉 CSP 已禁止的 `new Function` 路径）、`renderPage`（按布局宽度或缩放渲染，并按显示密度设置画布后备尺寸）与 `closePdf`。生成包不再无条件携带全部预置库：只有页面里出现名字的库才进包，许可证一律随包（它是插件再分发副本的一部分）。
- 样例一律按路径引用：拖入或选择文件时，宿主把本机路径交给工坊，页面只记录路径、扩展名与大小，从不读取或传输样例内容。此前设置窗口关闭了宿主的原生拖放处理，拖入的文件只能以浏览器 `File` 对象到达页面，工坊只好把整份内容读进页面再传回后端，大文件会失败。
- 视觉能力：试预览窗口打开时可「截图预览」，把窗口当前画面附在下一条消息上。截图为 PNG，由宿主的窗口捕获实现；只发送该任务最近一张，空白画面明确报错而不是把黑屏交给模型。

## 第一版实际实现与边界

界面修订（工坊仍为未发布的 0.1.0 基线）：工具 SDK 主动发送就绪消息，页面初始化不再使用等待父页面连接的顶层 await；宿主保留 onLoad 兼容路径且不重复关闭已建立的连接。供应商配置单独放在工坊插件设置页，生成页只保留设置跳转入口。拖入或选择文件后先显示文件卡片（名称、大小、类型）与生成入口，点击生成才调用模型（模式已在 2026-09-20 修订中合并，见上）。已安装列表仅渲染非空的单层来源分组。旧安装在与可信目录中的经过验证的包内容完全一致时补齐来源记录；缺乏历史凭据的旧版本显示为“已有插件 · 旧版安装”，不冒充官方来源。

本节记录当前代码状态；后续设计章节中超出本节范围的内容仍属后续验收或扩展目标。

- 工坊是 `plugins/workshop` 中的官方工具插件，通过官方源安装、更新和卸载，不随宿主预装。宿主提供通用工具桥和受控任务服务；需求分析提示、生成提示、界面及开发包描述由工坊插件提供。本地构建会把工坊加入开发源，尚未发布远程官方源。
- 已接通 API 配置、需求分析、需求输入与样例附加、多轮需求、文件选择/拖入、生成、语法与依赖检查、打包、试预览、安装、版本恢复和工坊内 ZIP 导出。生成中的任务可取消，重启后中断任务可手动继续。
- 生成范围是 JavaScript/CSS 预览界面，加固定的官方原生桥接程序。模型不能执行 shell 或编译原生代码；库由宿主取（pin + 完整性校验 + 不执行包内代码），运行时离线。JavaScript 使用 WebView iframe sandbox 和 CSP；没有实现 Windows AppContainer，也不宣称既有原生插件已获得操作系统级隔离。
- （已作废，见《生成物标准》）开发包曾提供离线 Three.js、FBXLoader 和 OrbitControls；工坊现在不带预置库，模型按需用 add_dependency 取库。通过选择器或原生拖放加入的样例仅保留本地路径，预览按需分块读取；发送给模型的是需求与文件类型等上下文，不含样例内容。
- SDK 指纹变化会阻止旧产物安装和导出，要求重建并重新试预览；当前不自动批量迁移旧项目。产物 SHA-256 和预览会话用于防止验证后改包、旧窗口回报；试预览成功回报不是完整功能质量证明。
- API 支持 Chat Completions 兼容接口。设置页按“服务 / 模型与长度 / 高级”分组：供应商预设一键填入常见服务商地址（含本机 Ollama、LM Studio、vLLM），可新增、编辑、切换、删除配置，填写名称、基础地址或完整接口地址、模型和 API Key，拉取模型列表、手动输入模型、测试连接并显示往返耗时。**上下文长度与最大输出是两个独立字段**：上下文长度只是本机参考值（不发送），最大输出留空表示交给服务默认值，两者都设置时要求最大输出小于上下文长度。宿主内置模型家族的参考长度表，按模型 ID（含网关的 `vendor/model` 命名）自动匹配并提示，可一键填入后手动覆盖。高级选项提供温度与请求超时。密钥按配置 ID 和服务地址分开保存在 Windows 凭据管理器，设置页按供应商显示是否已存密钥；运行中的任务固定使用启动时的配置和密钥。仅 HTTPS 或 localhost HTTP；不携带密钥跟随重定向。没有实现所有厂商专用协议。
- 输出预算按响应自适应，不再使用固定默认值：未配置时不发送预算字段；响应被截断（`finish_reason: length`）时自动加倍重试，上限取参考输出与上下文窗口中的较小者；服务拒绝预算参数时依次回退 `max_completion_tokens` 与省略字段。每次提高上限、每个回退都写入项目记录并在界面显示，不静默重试。
- 本机生成结果直接从构建目录准备稳定目录快照、核对目录内容指纹，再进入统一安装事务，不生成 ZIP。版本恢复也直接复制目录；只有导出分享时才创建 ZIP。旧版以 ZIP 字节计算指纹的开发期项目需要重建一次。
- 模型生成支持常见的 JSON 代码围栏响应；预览/构建失败诊断会在继续生成时传回模型；样例扩展名必须与生成清单保持一致，避免以更换格式绕过校验。
- 内置提示词不点名任何文件格式或库：只说明“样例扩展名来自项目上下文、扩展名决定要解析的格式”，并显式区分宿主插件打包格式（api:1 清单）与样例文件格式，避免把拖入的文件当成插件包或反过来把模型类依赖当成待预览格式。模型需要的库由它自己按包名与版本取（见《生成物标准》），提示词里不再有格式或库的清单。
- 宿主和插件共享离线 Lucide 完整图标索引，旧别名兼容，未知图标回退。图标数据由脚本自动生成，构建检查索引是否同步。
- 宿主插件管理只提供市场、分组、插件包导入与生命周期管理，没有导出入口。只有本机工坊项目通过试预览的产物可导出；原始样例、对话、密钥与项目状态不入包。导入前检查并暂存稳定快照，用户确认真实清单和权限后安装同一快照。
- 来源分为官方源、本机生成、本地导入、第三方源、未知；记录实际源标识。跨来源同 ID 覆盖被拒绝，需要先明确卸载。恢复旧生成内容会产生更高版本并要求重新预览，保持常规安装版本规则。

自动化覆盖包括 API 本地模拟、代码语法/依赖校验、分享包往返与篡改拒绝、来源冲突、工具权限边界、工具 SDK 和最小 FBX 解析。尚未使用真实用户 API、真实 Windows 桌面点击/拖拽及干净机器做完整验收，不能据此宣称达到下文全部发布标准。

补充端到端模拟测试：供应商配置保存/切换/重启恢复、无预选模型时获取模型列表、从已配置供应商进行需求分析和代码生成、构建目录安装、按需导出 ZIP。试预览成功回报由测试模拟，真实 WebView 视觉效果仍属桌面验收范围。

## 目标与范围

用户拖入文件或描述需求，由专用 Agent 生成符合 Ember Peek SDK 的插件，完成校验、构建、试运行、安装和重新预览，并能导出插件包分享给其他用户。

第一版包括需求与样例输入、多轮修改、自备 API、任务恢复、自定义插件管理、本地包安装、导出分享，以及宿主和插件统一的图标来源。首批只承诺经过验收的模板和依赖组合；不承诺任意格式都能自动生成。公开社区发布、云端构建、多 Agent 协作和任意原生依赖编译不在第一版范围内。

## 当前基础与缺口

- `docs/plugins.md` 与 `docs/specs/plugin-capabilities.md` 已定义 api:1、原生 JSON-lines、Web SDK、共享 UI、权限和生命周期规则。
- `scripts/build-plugins.mjs` 已实现仓库内插件构建及 SDK 资源打包，需要抽取为可面向独立工坊项目的工具，不能要求用户克隆宿主仓库。
- 市场具备准备与安装链路，但 `EntrySource` 当前只有 Remote，需增加本地导入与工坊产物入口，共用底层包校验和安装事务。
- 当前清单要求 executable，纯网页插件不能直接作为合法插件安装。
- `src/pluginIcons.ts` 是插件图标手写列表；`src/main.tsx` 另有工具栏图标映射，两者一起迁移。
- 原生插件以用户权限运行，现有 permissions 约束网页桥，不是原生进程沙箱。
- 现有插件入口围绕文件贡献设计，缺少无需文件的工具页面及工坊任务服务。

## 产品入口与操作

插件管理提供「插件市场」「我的插件」「插件工坊」。

「我的插件」分官方插件、自定义插件；自定义插件内部按 AI 生成、本地导入、第三方来源分组。单张卡片展示版本、来源、兼容状态、启用状态，提供设置、卸载；本机工坊项目另有「继续定制」。导出仅属于插件工坊，不是宿主插件管理功能。AI 生成只表示创建方式，不表示官方认证。

### 单一链路（原「简单预览」与「详细定制」，2026-09-20 合并）

输入需求 →（可选）附加样例 → 生成 → 校验 → 构建 → 试预览 → 安装并打开原文件。概念上仍保留原来的简单预览验收标准：拖入不调用模型，样例先落地为项目引用并显示出来，用户确认后生成才开始；默认只读、最少权限，使用现有 SDK 样式；仅在缺少必要文件、无法解析或需要超出默认范围时中止并说明；进度显示真实阶段、耗时、重试和取消入口，不以模型文本充当构建结果。区别是这些都不再依赖一段内置需求文本，用户写什么就是什么。

FBX 验收场景：加载静态几何、自动居中、鼠标旋转和缩放、重置视角；不包含动画编辑、材质编辑、导出转换。外部纹理由用户选择相关目录后按明确范围读取，不递归开放整盘。缺失纹理显示默认材质并提示；不支持的 FBX 变体明确报错。大型模型必须有大小、内存与解析时间预算，不把全部网格塞进受 8 MiB 限制的 open 响应。

### 多轮定制

支持仅输入需求、附加样例，以及多轮补充与对话式修改。需求历史随任务持久化，每次生成都能读到完整需求与上一次的失败诊断；后续修改以当前可用版本为基线生成候选版本，不覆盖正在使用的版本。试预览打开后可以把窗口画面截给模型，用于判断渲染结果而不是猜测。

### 不支持格式的引导

无可用 view 时先区分未安装、已禁用、插件失败、市场查询失败和确无匹配。市场有匹配时提供安装；确无匹配时提供「用 AI 创建预览插件」，带入格式和本地文件引用。元数据 overlay 不应阻止此入口出现。查询失败允许重试和主动进入工坊，不声称市场没有插件。

## 工坊与宿主边界

工坊通过官方插件源提供，与其他插件一样由用户安装、更新、停用和卸载，不随宿主安装包内置。首次引导可推荐安装；宿主只提供通用工具页面、凭据、任务执行、受限文件访问与包安装基础设施。停用工坊不影响已生成插件运行。

新增独立的工具扩展协议 `tool-api:1`（设计名称），与现有预览 api:1 分开解析和扫描，不向严格清单偷偷添加未知字段。工具页面有独立会话，不虚构文件贡献。工具清单、能力授权、页面桥和生命周期须先补规范与测试。生成的预览插件继续遵循现有 api:1。

第一版只有宿主内置注册的工坊身份获得构建任务服务能力；不能仅凭包声明相同 ID 获取权限。通用工具页面不意味着任意第三方工具都能执行命令或访问密钥。

工坊 UI 负责对话和状态展示，Rust 侧服务持有任务、模型调用、文件句柄和凭据。工具页面卸载后任务可继续，取消由显式操作触发；宿主退出/崩溃后从检查点恢复，不假装子进程仍在执行。

## API 与文件输入

第一版实现 OpenAI-compatible 服务适配器，配置服务地址、模型、API Key、上下文长度参考值与最大输出，支持连接测试和能力检查；其他协议通过后续适配器接入。不能把所有兼容服务都假定为支持工具调用、图片或相同流式格式，也不能假定都接受同一个输出预算参数。

凭据存 Windows Credential Manager，配置仅保留引用；只由后端发送到所选服务，禁止进入插件包、模型上下文、日志或导出文件。重定向不携带凭据跨主机。默认 HTTPS，本地模型允许 loopback HTTP。

文件拖入默认仅授予该项目本地样例使用权。默认发给模型的是格式、大小、探测结果及必要的脱敏诊断；原始内容或截图上传须在界面说明并由用户选择。样例、文件内文本和依赖文档作为数据处理，不能改变工具权限或覆盖任务规则。

显示请求次数、token 用量（服务提供时）与任务限额；金额仅在有明确单价配置时估算。网络超时、限流、服务不支持工具调用均需可恢复诊断。

## Agent 执行链路

状态：draft → analyzing → planning → generating → validating → building → testing → ready → installing → installed；另有 awaiting-input、failed、cancelled。导出是针对已验证版本的独立操作。

AI 负责理解需求、选择受支持模板、编辑代码和根据诊断修复；固定工具负责判断规范是否通过、编译是否成功和安装是否完成。

向 Agent 提供结构化工具：读取项目文件、查询图标、取库（add_dependency）、写入/修改文件、检查清单、试运行。禁止通用宿主 shell；安装与导出由应用流程发起，不能靠模型一句“成功”触发。

每个阶段持久化输入指纹、产物和状态；默认最多自动修复 3 轮，时间/token 预算可配置。取消终止该任务进程树，已安装版本不变。恢复时验证源码、开发包、依赖锁与构建产物指纹，失效阶段重新执行。

## 生成物标准（2026-09-21 固化）

这一节是生成插件的契约：宿主与校验按它执行，工坊提示词按它写。此前"开发包预置模块"那套描述作废——工坊不带任何预置库。

**包内文件**

| 文件 | 谁写 | 说明 |
| --- | --- | --- |
| `plugin.json`、`ui/index.html`、`ui/sdk.js`、`ui/sdk-ui.css`、`ui/boot.js` | 宿主 | 模型不可写；覆盖即拒绝 |
| `ui/view.js`、`ui/style.css`、`ui/<name>` | 模型 | 页面与它自己的辅助模块 |
| `ui/vendor/<name>` | 宿主（取库）/ 模型（自带） | 一层，不再分目录 |
| `dependencies.json` | 宿主 | 取库来源记录，随包分发 |

**取库（`add_dependency`）**

- 来源默认 `https://registry.npmjs.org`；`EMBER_LIBRARY_REGISTRY` 可指向内网镜像。只接受 HTTPS，本机地址（localhost/127.0.0.1/[::1]）可用 HTTP；tarball 必须与取库源同源，重定向不跟随。
- 版本必须确切（`0.5.4`）或留空取 latest；范围与标签拒绝——同一任务在不同日子必须产出同一个包。
- 只接受 `sha512-` 完整性哈希（源必须给出），下载后校验，不一致即丢弃，不修复也不警告。
- 解包只接受 `package/` 下的普通文件：链接、绝对路径、`..` 一律拒绝；上限 20000 个文件、解压 256 MiB、单文件 16 MiB、tarball 64 MiB。**不执行包内任何代码**（没有 npm install，没有 postinstall），这与"不运行模型自定义依赖安装脚本"是同一条约束。
- 落包只写 `ui/vendor/<文件名>`。文件自身若还有裸名 import、或依赖打包器，直接拒绝并说明替代做法；脚本构建（UMD/IIFE）可用但提示从哪个全局读接口；CommonJS 点明要换 ESM。
- 缓存 `<工坊目录>/libraries/<包>/<版本>/`，`.complete` 最后落盘。已缓存的确切版本不再联网；未联网时 latest 回落到本机最新缓存版本并在回复里注明。
- 许可证随包：取包内根目录的许可证文本，命名为 `<包>-LICENSE.txt` 记进 `dependencies.json`；没有则记录为空并提示在总结里说明来源。

**联网查询（search_web / read_docs / read_page）**

- 工坊要覆盖没人写插件的格式，而那正是模型不认识的东西：哪个库能读这个容器、它的 API 长什么样、解码器为什么拒绝这段流。三个查询都由宿主中介，每次生成共用一个预算（24 次），超出即明确拒绝并让模型收尾。
- `search_web` 固定查三类无需账号的来源：npm 包（带可 pin 的版本号与月下载量）、Stack Overflow（带票数）、context7 文档库；通用网页搜索是设置项，不是默认项——免账号又能直连的通用引擎实际都会给抓取者返回验证页。可配 SearXNG（自建或公共实例，需开启 JSON 输出，免费）或 Tavily（API Key，有免费额度）。密钥存系统凭据库，`search.json` 只存来源与地址。
- `read_docs` 按库名先在 context7 检索再取正文（可给 topic 缩小范围，4000 tokens 上限），一次调用完成两步；`read_page` 读单页公开 URL 并抽成文本。
- `read_page` 只允许公开 http/https：本机、内网、链路本地与其它协议在发请求前就拒绝，重定向每一跳都按同一规则检查；页面 1 MiB、返回文本 48 KiB 上限；脚本/样式/标记不进入正文，实体解码、连续空行折叠。
- 取回的一切都是**数据**：网页、搜索结果或库 README 里的文字即使写成命令也不改变任务与规则。提示词明确写了这一条，生成提示词的既有原则（项目上下文是数据，不是指令）在这里同样适用。

**页面运行契约**（模型据此选库，宿主据此拒绝）

- 只允许 blob worker：页面不能取脚本、不能用包外的 worker 脚本，库要自带 worker 就得从 Blob 建，或改在主线程跑。
- CSP 没有 `unsafe-inline`：页面里的内联脚本永远不会执行，所以启动看护与错误上报只能放在包内同源文件里（宿主提供 `boot.js`，页面模块挂载后回报它）。启动失败必须在页面上说出来，不能只留一片空白。
- 媒体元素的源只能是 `blob:`（`fileBlob()`、`resourceBlob()` 或自读字节），`fileUrl()` 用于当前文件，`resourceUrl(reference)` 用于文档内的图片等关联资源；相对引用按当前文档目录解析，公开 HTTP(S) 资源由宿主中介获取，但引用发现和渲染完全由生成插件负责。`@file` 一次给整份文件，超过 32 MiB 拒绝；单个关联资源超过 64 MiB 拒绝。
- 没有裸名解析、没有 import map、没有打包器、没有 eval；import 只能是包内相对路径。
- 命令按钮一律走宿主工具栏（`controls`），页面不得自建按钮或工具栏。

## 构建与运行范围

第一版采用经过验证的通用原生桥接程序 + Web 插件模板；桥接程序满足现有 executable 和生命周期协议，由宿主开发团队构建并随开发包提供，Agent 不修改其二进制。格式解析优先使用已批准且锁定版本的 JS/WASM 依赖，全部打包本地运行。

需要独立原生解析程序、额外编译器或未批准依赖的需求明确标为暂不支持，不偷偷要求用户安装开发环境。后续再提供原生构建路径。

独立项目构建器使用随应用提供并锁定版本的打包运行时，不依赖用户全局 Node/Rust；不运行模型自定义 npm scripts、依赖安装脚本或任意编译钩子。依赖通过确定的目录与锁文件解析。

构建、解析与试运行需要实际的 Windows 隔离方案验证：受限 token/AppContainer 可行性、目录 ACL、Job Object 进程树与资源限制，以及默认断网。Job Object 本身不是文件或网络沙箱。若 WebView/解析运行环境无法满足隔离要求，缩小执行范围或阻止该路径发布，不能用“独立目录”替代隔离。

隔离应延续到已安装的工坊桥接插件；依靠桥接程序的受信任身份/内容校验选择运行策略，不能相信清单自报安全。手动导入的任意原生程序仍属当前可信原生插件模型，安装前说明这一差异。

验证关卡：清单与路径 → SDK/依赖与离线资产 → 构建 → open/settings/release 协议 → 真实样例渲染和 presented → 交互验收。编译成功不等于预览成功；自动探测与用户实际预览结果分别记录。

FBX 使用哪个解析依赖由实现阶段的小型验证决定：须覆盖二进制/文本样例、旋转缩放、缺纹理、损坏输入和体积限制。不能通过验证则明确延期 FBX 支持，不能拿演示模型代替用户文件宣布成功。

## SDK 同步与升级

宿主发行物附带版本化开发包：native/web SDK、清单 schema、共享 UI、模板、图标索引、构建器、依赖目录、协议测试和能力描述。每个项目锁定开发包版本与内容指纹，Agent 只按该版本文档和接口工作。

宿主升级同步提供新开发包；新任务默认使用新版，既有项目保留原锁。插件版本独立于宿主版本，不批量替换已安装包内 SDK。升级时检查 api 及所需能力，不兼容项目可进入修复/重建任务，通过验证才换装，保留上一可用包。

开发包版本和完整能力需求存工坊项目元数据。第一版尽量不扩展预览清单；必须新增协议字段时正式版本化，维护旧包兼容规则，不能绕过 deny_unknown_fields。分享包的可运行性不能依赖只存在本机的项目元数据。

## 通用图标来源

第一版选 Lucide 作为宿主、插件身份图标、工具栏和插件 SDK 的共同图标来源。项目已依赖 lucide-react，统一来源可保持视觉一致，同时消除逐项维护名单。

从锁定版本的官方图标包自动生成完整名称索引和本地资源映射，按需加载本地资源；不把全量图标塞进首屏 JS，也不依赖在线 CDN。允许声明该版本提供的所有规范名称。更新依赖后自动更新索引，CI 校验图标资源和索引一致性。

第一版保留当前 kebab-case 字符串格式，例如 `"icon": "box"`，默认命名空间就是 Lucide，因此无需为冒号修改 api:1 校验。保留 40 字节上限前先验证全量名称；若发现不兼容，显式修改规范和校验，不能悄悄漏掉图标。暂不引入多图标集前缀。

现有工具栏 fit/actual/up/down 等语义名保留兼容别名；新代码优先使用正式图标名。宿主 UI 的静态导入仍可保留，但与动态解析器使用同一锁定版本。删除两份手写白名单，名称发现、搜索和预览来自自动生成索引。

Web SDK 新增查询/渲染图标的接口（具体函数签名实现前定稿），通过宿主受控本地资源取得图形，不向 iframe 暴露任意文件路径。生成时从索引选择真实存在的名称，禁止模型猜名称。构建检查所有静态声明，并在试运行检查动态 controls 图标。

未知名称或旧宿主缺少的新图标显示通用图标，开发诊断记录缺失但不阻止插件加载。离线、导出后安装、深浅主题均可用。图标来源可信不代表使用它的插件可信；官方来源标识由宿主独立显示。

仅接受名称引用，不接受远程 URL、插件提供的 SVG 字符串或脚本。官方资源在构建期处理并保留随包许可证。后续确需多个图标集时，可评估 Iconify 的集合格式和受控数据分发，逐集合处理版本与许可证，而不是信任整个公共 API 的所有内容。

选型依据（2026-09-17 查阅）：[Lucide React](https://lucide.dev/guide/react) 提供 React 图标与动态组件入口；[Lucide 许可证](https://lucide.dev/license) 列出 ISC 及部分 Feather 衍生图标的 MIT 声明。保留上游完整声明。[Iconify 图标集](https://iconify.design/docs/icons/icon-set-basics.html) 按集合组织数据，[Iconify 入门](https://iconify.design/getting-started/) 明确各图标集有各自许可证，因此不将聚合服务视为统一授权来源。

## 导出、分享与本地安装

第一版分享方式是导出标准 `.zip` 插件包；沿用根目录 plugin.json、bin/、ui/ 等既有布局。用户将文件发给他人，对方在插件市场的「安装插件包」里选中该文件、或直接把 `.zip` 拖到插件列表上即可导入，无需 API Key、工坊项目或开发工具就能预览。市场只接受 `.zip`：准备流程先复制为稳定快照，不直接执行可变源目录，本机工坊产物走同一套准备与安装事务。

导出入口仅位于插件工坊的本机项目与生成结果中，只导出该项目通过验证的生成版本，不依赖是否已经安装。宿主插件管理不提供导出按钮，官方插件、第三方插件和本地导入插件不能通过该入口导出。显示名称、版本、目标平台、文件大小及支持范围。下载式分享不等于发布到官方市场，不自动上传或联系他人。

打包按构建产物白名单收集，不打包整个项目目录。包括清单、程序、UI、必要运行依赖、许可证及简短使用说明；排除 API 配置、环境变量、聊天历史、原始样例、绝对路径、日志、缓存和本机来源记录。第一版不包含源码项目导出。

清理安装期 revision，按现有打包规则写入中性值并重新生成产物指纹；接收方分配自己的 revision。包哈希用于完整性，不表示作者认证。未实现签名验证前，不展示「已签名/已验证发布者」。来源信息由接收方安装流程记录，不能从包内继承官方身份。

准备导入时检查清单、平台、协议、解压大小/数量预算、路径穿越、链接/reparse point、文件缺失和可执行入口；检查不启动程序。之后展示来源和权限，再按用户安装操作进入统一事务。导入包默认归本地导入，即使包自称 AI 生成也不冒充本机生成项目。

生成插件使用 `user.<随机标识>` 的稳定 ID，显示名称独立。相同 ID 的本地包不能静默覆盖官方源/其他来源的安装；明确冲突后由用户选择替换或取消。正常更新按版本规则执行，内部回退使用独立事务保留原版本，不通过放开常规降级规则实现。

换装前遵守现有未保存变更保护，完成文件替换及注册后再标记 installed；失败恢复旧包与安装记录。成功后重新收集贡献，仅当原文件仍是当前目标时打开它，不能把用户从其他文件抢回。

## 持久化与模块拆分

数据分为工坊项目、任务记录、不可变已验证产物、安装记录四类。项目持有需求摘要、对话、样例引用、源码、依赖锁和开发包指纹；任务记录阶段、诊断及预算；产物含哈希和验证报告；安装记录含来源类型、获取方式、源标识、可选本机 projectId、版本和回退包引用。凭据单独存系统凭据库。

来源类型与获取方式分别建模，避免“第三方从文件导入”无法表达。分组优先级：受控官方源 → 本机生成 → 本地导入 → 第三方源；缺失来源的旧安装显示来源未知，不根据 ID 前缀推断官方。

建议新增工坊 UI 模块、工具页面协议与桥、后端 workshop 任务服务、开发包构建器、独立项目打包器、共享图标解析器；扩展安装准备入口与安装记录。工坊项目不写入仓库 plugins/，用户产物与官方开发源码分开。

## Pi 集成实现（0.1.0）

- 使用锁定版本 0.86.0 的 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`。Pi 承担对话、流式响应和工具循环，不再维护宿主自写的代码生成重试循环。
- 不引入终端 Coding Agent 的默认 Shell/文件系统工具。工坊只开放 `read_file`、`write_file`、`edit_file`、`validate`，可变文件限定为 metadata.json、ui/view.js、ui/style.css；宿主完成实际校验和最终包构建。
- Node 与打包后的 Agent 随工坊的 bin/ 分发，许可证随包提供；密钥只通过标准输入传递，不进入命令行或项目记录。Windows 子进程隐藏启动，取消任务终止进程。
- 用户配置 OpenAI Chat Completions 兼容接口；生成要求支持 SSE 和工具调用。无密钥的本机服务不发送 Authorization，网络请求禁止自动重定向。
- 流式文本、工具执行及文件事件进入工作台。草稿逐文件持久化，生成失败后可检查已有代码并继续。上下文/输出上限不作为用户表单字段；生成使用服务默认输出上限，截断请求继续已有文件。
- 本机安装直接使用已验证目录快照，只有导出分享才打 ZIP。工坊插件版本保持 0.1.0。

验证：`npm test` 先构建插件包，再运行 JavaScript 与 Rust 测试。真实供应商用例显式启用，读取 COMMAND_CODE_URL / COMMAND_CODE_APIKEY / 可选 COMMAND_CODE_MODEL；测试文件和安装目录均为临时目录。
