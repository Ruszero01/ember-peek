# 数据库预览插件

第一版提供**只读** SQLite 预览（官方 `ember.database`，0.1.0，匹配 `db`、`db3`、`sqlite`、`sqlite3`）。后缀只筛选候选：实际格式以文件头为准，不携带 `SQLite format 3\0` 的文件按「不是 SQLite 数据库」报错，不会被当作别的格式硬解释。

不提供编辑、SQL 执行、导出或写入；不支持加密数据库（SQLCipher 等）与旧式自定义加密。目标是快速看清「有哪些表、表长什么样、里面有什么」。

## 分层与只读保证

宿主仍只提供 `api:1` 的文件匹配、原生命令、控件、状态与生命周期，不识别数据库格式。原生进程用 rusqlite（SQLite 源码随插件编译）以 `SQLITE_OPEN_READ_ONLY` 打开用户文件：不写回、不建日志、不落地任何中间副本，也不声明共享解析源。网页侧**不读取文件字节**（因此不申请 `readFile` 权限），只通过 `call` 取结构事实与有界行页；视口里画的是宿主控件与插件自己的网格。

原生进程按会话持有连接：`open` 建立，`release` 回收；没有会话时宿主结束进程。进程若在预览仍然打开时被回收，后续请求以 `database-session-expired` 明确失败，由网页提示重新打开文件，而不是悄悄给出一份过期结果。

## 读取与预算

预算都落在「一次读取带回多少」，不落在「数据库有多大」：数据库文件本身不被整体读入，表可以任意大。

- 一次 `open` 最多列 **5000** 个对象（表与视图；`sqlite_*` 内部表除外），对象总数照实回报，列表被截断时侧栏与状态说明。
- 一页最多 **500** 行，设置项默认 200 行（范围 20–500）。读取时多取一行来判断是否还有下一页，因此视图（没有行数）也能正确翻页。
- 单个文本单元格最多 **4096** 个字符；二进制单元格最多取前 **64** 字节并转成十六进制。被截断时结果里带上原始的字符数／字节数，由网页说明，而不是让用户以为值就这么短。
- 行数统计最多扫 **100000** 行：达到上限即报「超过 100000」，不为了一个数字扫完整张表。视图不统计（统计会执行视图查询）。
- 表宽超过 **512** 列时明确报错，不出数据页：一页的 SQL 会按列展开，超过 SQLite 的表达式预算只会让错误更难懂。
- 每次请求的偏移量为负时按 0 处理；`count` 一律夹在 1–500。

值按 SQLite 的存储类编码，不由网页猜：整数不丢精度（按十进制文本给出），实数用紧凑写法（极大极小转指数形式），`NULL` 与空字符串在界面上可区分，二进制按字节数说明。文本里的控制字符（除制表符、换行、回车）替换为 U+FFFD，避免网格里出现看不见却影响判断的内容。

## 界面归属

- **宿主侧栏**（同一 `entry` 以 `role:"sidebar"` 挂载）列出全部表与视图，可筛选；由主视图用 `sidebar(true)` 打开，默认打开，设置可关。
- **主视口**只放当前对象的内容：数据网格，或该对象的结构页。不画工具栏、不画状态信息。
- **宿主控件**：表列表开关、结构／数据切换、上一页、下一页、页码标尺（只在行数可知且多于一页时出现）。
- **状态行**：对象名、表／视图、当前行区间、总行数（不可知或超上限时如实说明）、列数。
- **失败**：原生返回 `token[:detail]`，网页按界面语言成句；`open` 阶段的失败由宿主显示。

## 数据契约

`open` 的结果（宿主在 `ready` 载荷里给两份挂载）：

```json
{
  "format": "sqlite", "library": "3.46.1", "size": 40960, "empty": false,
  "pageSize": 4096, "pageCount": 10, "freelistPages": 0, "encoding": "UTF-8",
  "userVersion": 0, "applicationId": 0, "schemaVersion": 12,
  "objects": [{"name": "users", "kind": "table"}, {"name": "top", "kind": "view"}],
  "objectCount": 2
}
```

`structure`（参数 `{name}`）：`kind`、`sql`（建表语句，可为 null）、`columns`（`name`、`type`、`notNull`、`primaryKey`（主键内序号，0 表示不在主键）、`default`、`generated`）、`indexes`（`name`、`unique`、`origin`（`c`／`u`／`pk`）、`partial`、`columns`（表达式列名为 null））、`rows`（`{value, exact}`；视图为 null）。

`rows`（参数 `{name, offset, count}`）：`columns`（可见列名）、`rows`（每格是 `null` 或 `{kind, text}`，二进制为 `{kind:"blob", hex, bytes, truncated}`）、`hasMore`、`offset`。

被拒绝的名字不在 `open` 报出的对象列表里 —— 读取端只接受自己在打开时见过的标识符，标识符在语句里按 SQLite 规则加引号。

## 与宿主的分工

结构事实与行数据都来自原生进程，网页只负责呈现与导航；分页、结构切换、表列表开关是宿主控件，缩略图式的自绘控件不在视口里。这一版**不声明浮层**：数据库的事实（页大小、编码、SQLite 版本、对象数）放在侧栏顶部，只有一行，不需要一个可拖动面板。也不声明 `prepare`：窗口尺寸与内容无关。

## 已知限制

- 存在未合并 WAL 或文件被其他进程独占时，只读打开可能失败并报明确错误；插件不会复制数据库或创建临时副本（那会把「只读」变成另一份可能过期的数据）。
- 不解析触发器、视图查询计划、外键约束与虚拟表的模块参数；结构页给的是列、索引与建表语句。
- 行序是 SQLite 返回的顺序（没有 `ORDER BY`），翻页期间若文件被别的程序修改，页边界可能移动。
- 不还原数据类型的格式化（日期、布尔、JSON 等按存储类显示）。
